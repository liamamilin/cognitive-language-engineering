# CLE 结构核心版

**子体系 v0.2 · 基于初步冻结的 CLE v0.5 · 已冻结 · 2026-10-01**

保留原体系的骨架，优先掌握能反复用、值得用的组件。

本版按原来的原则、模型、机制、任务、算子、语言模式、协议、应用与评估组织。所有原有 ID 和含义保留；只改变学习与调用的优先级。原“实用核心 v0.1”的三问入口不再承担核心体系结构。

[六项原则](#principles) · [四类模型](#models) · [机制](#mechanisms) · [工程层](#engineering) · [筛选依据](#selection)

## 保留什么，如何精简 {#selection}

“核心”指在**学习、表达、日常判断、沟通和基本任务协作**中预计反复复用、能解除关键缺口的部分。频率受应用场景影响；权限管理对某些角色可能高频，本版暂不把它当人人先学的内容。这里没有真实频率统计，也没有已经验证的收益排名。

筛选同时看四点：跨任务复用、删去后的关键损失、学习与调用成本、原组件的依赖。重要但专门的内容保留升级入口；复合组件必需的支撑不能为了数字少而删掉。

| 层 | v0.5 完整版 | 本版主讲 | 支撑或条件展开 |
| --- | --- | --- | --- |
| 原则 | 6条 | 6条全部保留 | 保留原边界 |
| 模型类别 | 4类 | 4类全部保留 | 不按相同裁剪比例分配 |
| 模型接口 | 81项 | 23项 | 8项支撑，共31项；其余50项转扩展 |
| 机制家族 | 12项 | 7项 | 其余5项在特定解释任务中展开，原映射不改写 |
| 算子／主语言模式 | 34／36项 | 15个算子及对应15个主模式 | 复杂规格、权限、因果与特殊变体转扩展 |
| 协议 | 13套 | PR05完整保留 | 其他协议按需回原版，不冒充已被精简版完整覆盖 |
| 连接与结果 | 8个Bridge／3个Outcome | 6个Bridge／3个Outcome | 连接是分析关系，不是必经流程 |
| 应用／评估 | 独立层 | 保留两例与最小检查 | 专业研究与复杂任务评价回原版 |

31项约为原81项的38%，并不是严格20%。这个比例来自依赖和用途取舍；“2/8”用于找高价值部分，不作为必须凑出的数字。**23项主讲与8项支撑不是同等学习负担，也不是一次任务清单。** 完整逐项保留／暂缓理由见[筛选审计](SELECTION.md)。

## 六项基础原则 {#principles}

沿用母体系，不另造简化原则。下表为阅读摘要，定义与证据边界以[Core Spec](../CORE_SPEC.md)为准。

| ID | 原则 | 核心要点 |
| --- | --- | --- |
| P1 | 表征原理 | 世界、内部表征、语言表征分开；展开不能制造事实 |
| P2 | 语境原理 | 功能取决于主体、目的、前文、媒介、关系和状态 |
| P3 | 共同背景原理 | 共享有范围与确认依据；共同接受不等于真实 |
| P4 | 语言行动原理 | 请求与安排依赖有效条件；声明不自动创造权限 |
| P5 | 语言介导认知原理 | 语言可参与部分认知；具体变化需要检查 |
| P6 | 形式敏感原理 | 表达形式可能影响加工与选择；改写不保证改善 |

六条中有建模立场、理论主张与局部实证命题，不能当六条同等类型的自然定律。详见[证据规范](../EVIDENCE_SPEC.md)。

**原结构的两条连接仍保留。** 解释视角由原则组织模型／变化与机制假设；工程视角从任务与当前状态选择算子／协议，用语境化模式尝试改变，再检查状态、现实结果与成本。机制、算子、模式和协议允许多对多关系，不是同一层的名称替换。

Task是需要解决的工程问题，Application是带领域约束的实际使用情境；两者不是M4中已成立的任务关系。M0仍是总闭环名称：现实／经验、表征与认知、语言与互动、社会或技术行动、结果、反馈；它不是第五类模型，也不是每次必经的六步。

## 四类模型：保留最常用的状态接口 {#models}

四模型仍是原来的分析视角。它们分别回答：**内容怎样表示、个人能怎样识别和使用、双方共享了什么、社会任务关系发生了什么。** 同一事件可以同时落入多个视角；状态接口不是问句，也不是机制。

### M1｜表征状态模型 {#m1}

主讲4项。先学习区分、表达和两种分辨率转换，完整的类别、抽象与概念建构留作扩展。

| 原ID／阅读名 | 状态变化 | 最小检查 |
| --- | --- | --- |
| [R-P2 表征区分](../models/M1.md#r-p2) | 混合特征 → 可区分特征 | 写出的差异能支持不同描述；不直接证明人理解了 |
| [R-P5 语言编码](../models/M1.md#r-p5) | 待表达内容 → 语言表征 | 关键含义、来源和未知得到表达；理解另查 |
| [R-P6 压缩](../models/M1.md#r-p6) | 详细表征 → 压缩表征 | 保留任务相关内容，重要材料可追溯 |
| [R-P7 展开](../models/M1.md#r-p7) | 压缩表征 → 属性、事实或关系 | 原材料、解释和新生成细节分开 |

M1中的“已写出区别”不等于M2中的“人能独立区分”；这正是保留两类模型的价值。[完整M1](../models/M1.md)中的分类、抽象与概念形成依然重要，但不是本版优先训练的四项。

### M2｜个体认知状态模型 {#m2}

主讲11项，支撑6项。保留从可识别内容，到目标、判断、选择与计划的常用接口；不把它们改成强制顺序。

| 原ID／阅读名 | 状态变化 | 最小检查 |
| --- | --- | --- |
| [C-P2 显化](../models/M2.md#c-p2) | 隐含或未被识别 → 当前可识别 | 先确认当前内容；有前状态才判断本次显化 |
| [C-P8 备选生成](../models/M2.md#c-p8) | 单一／缺少候选 → 实质不同候选 | 差异会改变判断；候选尚未证实 |
| [C-P16 期望状态构造](../models/M2.md#c-p16) | 偏好方向 → 可表征期望状态 | 能说明变化后有什么不同；不锁死手段 |
| [C-P18 目标采纳](../models/M2.md#c-p18) | 期望状态 → 主体采纳的目标 | 本人愿意投入追求；不等于社会承诺 |
| [C-P19 证据关联](../models/M2.md#c-p19) | 主张与材料未关联 → 支持关系 | 材料支持哪一步，哪些仍未知 |
| [C-P20 不确定性表征](../models/M2.md#c-p20) | 未知未区分 → 明确未知与范围 | 指出未知处、依据和更新材料 |
| [C-C1 具体化](../models/M2.md#c-c1) | 模糊对象 → 任务所需具体对象 | 能区分满足／不满足描述的情境 |
| [C-C8 标准形成](../models/M2.md#c-c8) | 标准缺失／隐含 → 可用判断规则 | 规则能判例，或按规则定位缺材料 |
| [C-C9 候选评价](../models/M2.md#c-c9) | 候选集合 → 带依据与未知的评价 | 同一适用规则与材料可追溯；允许不可比较 |
| [C-C10 决策形成](../models/M2.md#c-c10) | 待选情境／评价 → 选择及理由 | 选项、依据和重开条件明确；选择不是执行 |
| [C-C13 计划形成](../models/M2.md#c-c13) | 采纳目标／选择 → 实现路径与依赖 | 下一步能开始；关键条件和回退明确 |

**支撑6项：** [C-P3区分](../models/M2.md#c-p3)、[C-P7参照](../models/M2.md#c-p7)、[C-P13边界](../models/M2.md#c-p13)、[C-P14关系](../models/M2.md#c-p14)、[C-P15优先关系](../models/M2.md#c-p15)、[C-P21选项选择](../models/M2.md#c-p21)。它们直接支持具体化、标准、评价、决策与计划；在相关组件中理解，不要求先独立背六张卡。C-P19仍是C-P14的特化，不算新独立机制。

例如，C-C8标准形成依赖显化、区分、候选、边界、关系和优先级；如果删掉这些依赖而只保留“标准形成”四个字，核心版就会失去可解释的结构。本版保留这些关系，已有部分在一次调用中可以复用。

完整因果结构、系统假设审查、信念校准与实施意图训练转[完整M2](../models/M2.md)。方向尚未形成时，可回C-P17/C-C6；不能由协助者替人决定目标。

### M3｜共享认知与互动状态模型 {#m3}

主讲4项。优先处理是否理解、歧义、含义与真正的分歧。

| 原ID／阅读名 | 状态变化 | 最小检查 |
| --- | --- | --- |
| [I-P1 共享确认](../models/M3.md#i-p1) | 假定共享 → 有范围的确认依据 | 按任务用新例、预测或操作反馈检查 |
| [I-C2 澄清](../models/M3.md#i-c2) | 多种未决解释 → 局部澄清 | 具体情境中能够确认所指 |
| [I-C3 含义对齐](../models/M3.md#i-c3) | 不同解释 → 足够一致的解释 | 共同含义与未约定部分明确；不等于同意 |
| [I-C6 分歧结构化](../models/M3.md#i-c6) | 笼统不一致 → 可定位分歧 | 绑定双方立场和冲突对象；允许继续不同意 |

共同模型、工作框架、完整共同背景维护和分歧处理结果转[完整M3](../models/M3.md)。定位分歧不等于解决分歧，准确理解也不等于同意。

### M4｜语言行动状态模型 {#m4}

主讲4项，支撑2项。保留日常协作中的基本任务关系；正式承诺、责任分配、授权与治理需要更多条件，转扩展。

| 原ID／阅读名 | 状态变化 | 最小检查 |
| --- | --- | --- |
| [A-P1 请求形成](../models/M4.md#a-p1) | 无有效请求 → 可响应请求 | 对象、行为、响应方式和接收依据明确 |
| [A-P9 任务定义](../models/M4.md#a-p9) | 任务对象不明 → 可辨认任务对象 | 任务及版本可指认，缺字段明确 |
| [A-P10 任务接受](../models/M4.md#a-p10) | 任务已定义／指派 → 执行方明确接受 | 确认任务版本、条件与期限；义务来源另查 |
| [A-P11 任务完成](../models/M4.md#a-p11) | 待完成／已提交 → 按标准判定完成 | 交付证据、标准版本和关闭依据可追溯 |

**支撑2项：** [A-P14交付物定义](../models/M4.md#a-p14)使结果可找到；[A-P16验收标准绑定](../models/M4.md#a-p16)把判断规则纳入任务约定。M2的C-C8形成规则，M4的A-P16登记规则被任务采用，两者不能合并。

这只覆盖基本任务关系，不宣称完整[A-C6可执行规格](../models/M4.md#a-c6)、承诺生命周期或有效权限已经形成。遇到资源、角色、权限、约束或旧安排有争议，就转[完整M4](../models/M4.md)，不把未主讲字段当成可以忽略的条件。

## 机制层：先掌握七类解释问题 {#mechanisms}

机制仍回答“变化可能怎样发生”。模型的变化接口、机制解释和操作规格分开。以下保留原机制家族ID及定义边界，只选择先主讲哪些家族。

| 原ID／家族 | 主讲理由 | 过程假设与检查 |
| --- | --- | --- |
| [ME02比较／分类／结构映射](../MECHANISMS.md#me02) | 学习、区分与关系理解反复使用 | 并置与映射后，是否能用区别处理新例；三类活动不是单一机制 |
| [ME03编码／外化／提取](../MECHANISMS.md#me03) | 表达、总结与重新调用的基础 | 是否保留关键内容、改善调用；写出不保证理解或记住 |
| [ME04元认知监控／信心表征](../MECHANISMS.md#me04) | 防止把流畅、自信和猜测当可靠判断 | 看依据、错误检查与未知是否明确；自述不能替代过程测量 |
| [ME08解释／证据评价／模型检验](../MECHANISMS.md#me08) | 判断可靠性和纠错的关键 | 材料支持哪步、能否区分候选；能解释不等于真实 |
| [ME09目标调节／采纳／计划](../MECHANISMS.md#me09) | 连接目的、资源投入与后续行动 | 检查采纳、条件与实际行为；细计划不保证行动 |
| [ME10共享确认／互动修复](../MECHANISMS.md#me10) | 沟通误解与协作接口反复使用 | 反馈能否定位和修复误解；不追求完美一致 |
| [ME12构成规则／社会状态更新](../MECHANISMS.md#me12) | 虽非每次单人任务调用，但缺它会把M4退化为话术 | 查角色、来源、接收和生效依据；主要解释规则判定，不冒充心理因果机制 |

**另五类按条件展开：** ME01注意／搜索分配、ME05情境评价／框架、ME06备选／反事实生成、ME07未来模拟、ME11语境解释／语用推理。它们不是低价值或已被七类替代；本版不为每个候选过程单设主讲卡。例如遇到框架影响选择时展开ME05，生成备选时可查ME06，构造未来情境时可查ME07。

原组件可能同时映射主讲与条件机制。**筛选不删除或重写这些映射，也不把ME05的过程改名为ME09。** 所有候选映射仍默认E0；文献仅支持原文限定的局部主张。机制主讲顺序是教学取舍，不是实证效应大小排名。

### 优先完整掌握 PR05 {#protocol}

保留[PR05评价与决策](../engineering/PROTOCOLS.md#pr05)的完整结构：入口与目标、六个使用算子、步骤、分支／回退、达成检查、未达成出口、停止、最小输出、失效和评价。

1. 明确决定主体、决策对象、约束与时间。
2. 按需补候选，包括不做、分阶段或可逆试验。
3. 先查必要条件，再用适当规则比较；依据、偏好、后果与未知分开。
4. 权衡继续搜集信息的价值与成本，决定采取、试验、暂缓或退出。
5. 保留停止理由与重开条件；选择之后，才按需进入计划或协作。

达成检查是“有依据的明示决定及重开条件”，不是必须选出一个行动方案；没有作出决定仍保留待选。关键未知阻止不可逆决定时先查，不能用缺失值打零制造最高分。上文是阅读摘要，完整条件以原PR05卡为准。

**停止与最小输出：** 明确当前选择或暂缓理由，并知道何时重开；保留选择对象、规则、依据、未知、停止理由与重开条件。注意偏好冒充证据、缺失值填零、决定冒充执行和无限搜索四种失效。按前后状态、实际结果与成本评价；走完协议不证明它有效。

其他12套协议仍有价值，但不放进本版必学集合。表征与表达复杂时读PR01；含义问题读PR07，分歧问题读PR08；委派、责任和规格复杂时读PR09；需要条件动作时读PR10；系统结果复核读PR12。它们的完整组件没有被本版偷偷纳入。一个算子足够时不需要协议。

## Bridge、实际结果与评估 {#feedback}

先掌握六个连接：

| 原接口 | 核心关系与边界 |
| --- | --- |
| [B-C1](../BRIDGES.md#b-c1) | 语言表征与个人认知变化连接；更多文字不是能力证据 |
| [B-C2](../BRIDGES.md#b-c2) | 表达、接收解释与互动确认连接；不是从一个头脑直接复制到另一个 |
| [B-C3](../BRIDGES.md#b-c3) | 意图进入有效请求；发出、收到、接受分别检查 |
| [B-C4](../BRIDGES.md#b-c4) | 理解与社会采纳连接；核心只展开任务接受，不展开全部承诺与授权 |
| [B-C5](../BRIDGES.md#b-c5) | M2判断标准经表达和确认进入M4验收绑定；个人标准不自动成为任务约定 |
| [B-C8](../BRIDGES.md#b-c8) | 结果反馈进入表征、判断、共享或安排更新；发现需改与实际生效分开 |

B-C6复杂协调与B-C7影响归因按需回原版。保留Bridge的关系定义，不要求一轮走完其全部端点；例如B-C3提及完整目标形成，不规定每次请求前必须调用全部C-C7。

[O-C1观察、O-C2核验、O-C3更新](../OUTCOMES.md)全部保留。一次最小评估区分四件事：产物是否存在、当前状态是否有依据、本次是否发生变化、改善能否归因于操作。没有前状态不倒推“以前不会”，没有对照或其他排除材料不宣称效果因果。

日常只留下支持下一步所需的依据、结果、未知和决定；长期能力提升用独立新例、延迟调用和实际结果检查。具体框架沿用[评估规范](../evaluation/EVALUATION.md)与[训练路径](../learning/TRAINING.md)，不设新的总分或效果等级。

## 两个例子：从原结构调用 {#examples}

以下为构造示范，展示组件关系，不是实际效果报告。每个例子只调用需要的项。

### 学到一个概念，但容易混淆

**任务：** 学会区分两个概念，并独立用到新例。

- M1：用R-P2写出关键区别，R-P5表达；R-P6压缩成可重用摘要，必要时R-P7展开例子与来源。
- M2：C-P2确认自己当前的判断，C-C1具体化卡点，C-C8形成新例检查规则；不是把漂亮摘要当作已经掌握。
- 工程：对象模糊调用OP09，摘要分辨率不对调用OP33；若解释会影响事实判断，再用OP13，不强制走PR05。
- 机制：可考虑ME02/ME03/ME04，作为过程候选；正确答案不是这些机制已被证实。
- 结果：独立处理新例，进入O-C1/O-C2；据错误决定是否修订，进入O-C3。AI代写答案与本人表现分别登记。

单人学习可以不进入M3/M4；四模型保留不代表每次四模型齐上。

### 请协作者做一份比较材料

**任务：** 获得能支持当前选择的比较材料，而不是立即建立完整团队治理。

- M2：C-P16说明所需变化，C-P18确认追求；C-C8明确比较规则。选择本身未明确时，按PR05处理，不替协作者预填事实。
- M1：R-P5把任务内容编码为可理解表达；必要时R-P7展开“比较材料”的对象与条件。
- M3：I-C2/I-C3处理歧义，I-P1检查关键含义；若双方标准不同，用I-C6定位，不把不同意当没理解。
- M4：A-P9定义任务，A-P14说明交付，A-P16绑定检验规则；A-P1形成有效请求，再据响应检查A-P10。任务接受不证明资源充分，AI响应也不证明人类式承诺。
- 机制：ME03、ME10与ME12解释不同层的过程问题；复杂规格调用OP28/PR09时回完整体系，不声称已只靠基本任务卡完成A-C6。
- 结果：实际交付经O-C2与有效关闭依据检查A-P11；有权角色、权限来源或旧义务有争议时立即转扩展。

这个例子保留了M2标准与M4验收绑定、M3理解与M4接受的区分。它正是结构核心版应保留的能力，而不是只给“下一步做什么”的泛用问句。

## 学到哪里，何时回到完整版 {#boundary}

先能辨认四个模型的观察对象，再针对当前任务学习主讲接口；支撑项在对应复合组件中展开。机制用于解释假设，算子用于尝试改变，协议用于组织任务，评估用于查结果——层次不互换。

本版成功标准是：遇到日常例子，能定位相关域与缺口，选择适用操作，说明检查与边界。不是记住23个编号，也不是承诺覆盖所有任务。

**升级条件：** 关键偏好仍未知；需要因果识别或完整概念建构；需要共同系统模型；涉及正式承诺、责任分布、授权、规则、复杂依赖与旧安排修订；或者需要严谨的效果归因。回[完整v0.5](../index.md#_2)或[失效诊断](../evaluation/FAILURE_ANALYSIS.md)，不把少学误作现实不存在。

v0.2已于2026-10-01按用户要求冻结为后续打磨的基线。以后依据实际使用中“总要返回查哪项”“哪些长期不用”“哪里因缺组件失败”在新版本调整主讲集合，保留本版冻结快照；母体系v0.5定义保持当前冻结内容。
