# 002｜模型、接口粒度与行动边界

状态：已纳入 v0.4。依据：用户授权整套体系打磨。

问题：原有模型名称不一致；显化、生成等通用接口与特化重复；目标、评价标准、内部计划和社会行动容易混用；共享理解和请求完成容易被过度判定。

决定：模型作为可重叠分析视角；P 是当前工程粒度的变化接口；保留 ID 并标特化。内部采纳、计划和实施意图属于 M2；共同解释属于 M3；社会安排属于 M4；实际结果独立登记。新增接口只补现有 Registry 无法清楚表达的输出。

结果：新增 M2 八接口、M4 一个异常更新 Composite；Bridge 和 Outcome 连接域间过程。更多编号会增加使用成本，因此实际调用从任务进入而不是记住全表。
