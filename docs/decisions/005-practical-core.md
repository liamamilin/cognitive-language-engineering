# 决策005｜冻结母体系，抽取少而实用的核心

日期：2026-10-01。母体系 Core v0.5；子体系 v0.1；整合快照 project-v0.5.1。

## 授权与目标

用户初步冻结 CLE v0.5，要求抽取最核心、最小但足够重要的子体系。筛选考虑高频复用、人的能力提升与收益；进一步明确少而实用，不追求完整却难用。子体系制作阅读网站，入口置于 v0.5 首页“阅读路线”下。沿用此前确定的 GitHub Pages 方案。

## 取舍

日常调用保留三问：卡在哪、怎样算改善、下一步和检查点。六个动作按缺口调用，不强制顺序、不强制填表或打分：说具体、定改善、定检查、换个选项、查依据、选一步。三问承载常用组合，六个动作承担必要修补。

保留 OP09、OP16、OP17、OP18、OP11、OP13、OP20、OP21 的既有边界。结果回看沿用 O-C1—O-C3；多人任务才调用 OP23 式共享确认。复杂比较、因果分析、权限与正式社会安排回到完整体系。八个核心算子不意味着每次执行八项操作。

主张—材料、目标—采纳、规则—核验、计划—执行、理解—同意等区别保留在短句和示范中，术语与映射表折叠到末尾。没有另设新的 Primitive、机制或效果等级。

## 网站与冻结保护

一页独立阅读样式，正文只维护一份 Markdown；与母体系同次构建，同一 Pages 下使用 `essentials/` 路径。首页入口严格位于“阅读路线”部分。子体系的返回入口和组件链接支持双向阅读。

只增加入口、子体系及相应维护／呈现配置，不修改初步冻结的母体系理论正文。原 project-v0.5.0 压缩包和校验清单归档；打包前以原清单逐页比对冻结内容。

## 验证范围

检查源链接、页面锚点、严格构建和生成网站的本地资源／跳转。构造示范不是使用试验；没有频率数据、收益比较或迁移研究，“2/8”作为选择原则，不写成已经量化验证的结果。
