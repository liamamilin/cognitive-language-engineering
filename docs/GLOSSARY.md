# 术语与易混边界

| 术语 | 本版工作含义 | 易混边界 |
| --- | --- | --- |
| Representation | 对对象、经验或关系的表示 | 表示存在不等于真实或掌握 |
| State | 任务相关的系统描述 | 可观察迹象不等于完整心理状态 |
| Transition | 可辨认的状态变化接口 | 不是语言操作，也不是机制 |
| Mechanism | 过程解释候选 | 现象标签与可检验过程区分 |
| Task（工程层） | 使用语言要解决的问题 | 与 M4 社会任务对象区分 |
| Task（M4） | 主体／系统之间建立的行动要求对象 | 可以已定义但未接受或不可执行 |
| Operator | 可复用操作规格 | 同一算子可有多个模式 |
| Pattern | 可实例化语言形式＋适用条件 | 实际效果须含使用语境 |
| Protocol | 含分支、回退、停止的操作组织 | Protocol 可以只有必要的少量步骤 |
| Need | 需求／缺口的工作表达 | 有需求不代表形成目标 |
| Value | 较长期重视的状态或原则 | 与具体 Subjective Value 区分 |
| Subjective Value | 当前情境下的主观评价 | 不等于证据可靠性或社会价值 |
| Preference | 情境中的趋向或比较倾向 | 不要求稳定、完整排序或实际选择 |
| Desired State | 有特征的期望状态 | 可包含方案，但须保留上层目的 |
| Goal | 主体采纳并准备追求的对象／状态 | 不以数字、时限齐全作为存在条件 |
| Plan | 实现过程及依赖组织 | 计划不保证资源、授权或执行 |
| Implementation Intention | 线索—行动条件绑定 | 内部形成通常属于 M2 |
| Commitment | 按规则建立的主体间义务关系 | 内部 goal commitment 用 Goal Adoption 表达 |
| Criterion | 用于判断的规则或要求 | 与维度、指标、阈值区分 |
| Dimension | 从哪个方面评价 | 指出维度未必提供判断规则 |
| Indicator | 可观察迹象或代理 | 与目标之间联系需要依据 |
| Metric | 测量与计量方式 | 数字不自动更客观 |
| Threshold | 达到、排除或触发的界限 | 不保证整个对象都可排序 |
| Evidence | 与主张／判断相关的材料及依据 | 有来源不等于支持；想象不是观察证据 |
| Shared Information | 主体持有任务所需共同信息 | 不自动共同知道彼此持有 |
| Shared Meaning | 任务所需的解释一致 | 不等于对主张同意 |
| Shared Model | 共同使用的系统结构与过程表征 | 可以共同错误 |
| Shared Frame | 本次工作范围与视角 | 不等于唯一正确框架 |
| Common Ground | 有理由互认为可共同调用的背景 | 带范围、版本与争议状态 |
| Responsibility | 对结果或角色范围负责 | 与执行任务和决定权限区分 |
| Authority | 根据适用规则有效的决定／控制权 | 与主张、社会认可、技术凭证区分 |
| Acceptance | 对指定安排的接受事件 | 不是所有义务的唯一来源 |
| Completion | 按约定条件判定完成 | 提交、质量满足与社会关闭分别记录 |
| Calibration | 预测或信心与结果的对应质量 | 明确未知或自信降低不构成统计校准 |

这些是 CLE 内部使用约定，不声称统一所有学科的术语含义。

## 使用时再区分的六个词

| 术语 | 约定 |
| --- | --- |
| Artifact／产物 | 可检查的文本、材料或配置；存在不等于正确或被主体掌握 |
| Target Attainment／目标达成 | 对指定状态与范围已有支持依据；不自动说明是本次形成 |
| Termination／结束 | 一次调用停止的方式和原因；暂停或拒绝不替代目标判定 |
| Baseline／前状态 | 操作前可用于比较的材料；缺失不能默认为主体不会 |
| Reuse／复用 | 直接利用原已具备且仍有效的状态，不重复制造 |
| Influence／影响 | 他方状态受影响的现象；所求改变、发生与归因分别记录 |

“好”“有效”“完成”每次应说明具体指产物、状态、任务结果、关系关闭还是效果。这里不增加新的 Primitive，只改进使用判断。


## 模型分组的固定命名

模型正文的分组统一使用一个固定中文词及对应英文术语。标题使用“中文（English）”，讲解承担范围说明；讨论与后续修订沿用这套名称。背景对应既有术语Common Ground，保留其完整英文名称。

组名标明一组接口的主题；具体接口的定义仍分别保留。例如目标组包含偏好、期望和目标采纳，角色组包含责任、权限与角色关系；名称简化不将这些概念视为同义。Feature组包含特征选择和区分，Selection继续用于具体选择接口的名称。

| 模型 | 固定名称 | 本组范围 |
| --- | --- | --- |
| M1 | 特征（Feature） | 选择任务相关特征，并将混合成分区分开。 |
| M1 | 概念（Concept） | 通过分类、抽象和概念形成组织可调用的表征。 |
| M1 | 表达（Expression） | 将内容编码为语言，并调整压缩与展开的程度。 |
| M2 | 对象（Object） | 聚焦、识别并界定当前认知内容。 |
| M2 | 关系（Relation） | 对照对象，辨认异同、参照与关系结构。 |
| M2 | 问题（Problem） | 形成和组织问题，生成候选并检查解释与假设。 |
| M2 | 目标（Goal） | 区分偏好、期望变化及主体采纳的目标。 |
| M2 | 决策（Decision） | 形成规则、评价和优先关系，作出有依据的选择。 |
| M2 | 计划（Plan） | 组织实现路径及情境线索—行动绑定。 |
| M2 | 反思（Reflection） | 审查材料、未知与判断过程，保持或调整信念。 |
| M3 | 信息（Information） | 形成共同材料，并检查接收、理解与可调用范围。 |
| M3 | 对齐（Alignment） | 澄清并协调含义、系统模型和工作框架。 |
| M3 | 分歧（Disagreement） | 定位不一致，并确认一致、保留分歧或暂停。 |
| M3 | 背景（Common Ground） | 更新已确认、争议、失效与尚未共享的共同内容。 |
| M4 | 请求（Request） | 形成可响应的请求，并辨认响应状态。 |
| M4 | 规格（Specification） | 定义任务对象，绑定目的、范围、交付、约束与验收。 |
| M4 | 任务（Task） | 辨认执行方的接受，以及按标准核验后的完成。 |
| M4 | 角色（Role） | 组织责任、有效权限与角色之间的关系。 |
| M4 | 承诺（Commitment） | 理解承诺怎样建立、履行、解除或重新协商。 |
| M4 | 协作（Coordination） | 组织依赖、协调、规则、治理与关系修订。 |


## 接口名称的呈现

接口标题统一为“中文名称（English Name） · 稳定ID”。中文名称以模型卡片标题为准，模型目录及完整连接索引使用相同名称；英文名称与原接口ID保留追溯。组名仍标明主题，例如表达（Expression）组下包含语言编码（Linguistic Encoding）、压缩（Compression）和展开（Expansion）。

容易混淆的接口在相关卡片中增加“相邻区别”，直接说明它们处理的不同内容或关系，关联名称可点击查看。
