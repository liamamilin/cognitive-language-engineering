# M1. Representation State Model｜表征状态模型

版本 v0.6。状态：完整体系工作版，尚未冻结。

观察表征结构及其转换。经验、特征、类别、概念与语言形式是可往复组织的网络，不是必须逐项走完的流水线。

表征变化与主体认知变化可同时发生；M1 记录表示了什么，M2 记录主体能识别或使用什么。

本模型登记 8 个接口：7 个 P 编号、1 个 Composite。P 表示当前工程粒度，不是心理机制不可再分的证明。

**接口组织：** 本模型按特征（Feature）、概念（Concept）、表达（Expression）组织接口。特征是表征中被选取和区分的内容；对不同实例的特征进行分类，并抽象其中的共同关系或结构，可以形成概念。概念使这些内容能够被重复识别和调用；表达则将特征、概念及其他内容组织为语言表征。表达可以压缩或展开，使相同内容以不同详细程度呈现，并帮助重新辨认其中的特征和概念。由此，特征提供材料，概念组织材料，表达使组织后的内容进入语言。

[原则](../learning/PRINCIPLES.md) → [四模型](../learning/MODEL_GUIDE.md) → 本模型接口 → 对应算子 → 语言模式。重点联系P1、P2、P6、P7，各原则仍适用于跨模型任务。先辨认接口要观察或推动什么，再读方法及例句。

## 特征（Feature） {#feature}

<a id="r-p1"></a>

### 特征选择（Feature Selection） · R-P1

**状态变化：** 未组织的任务相关经验 → 已选择特征。

选择当前任务所需的特征；经验并非客观无结构。

**相邻区别：** 特征选择决定表征保留哪些内容；[聚焦](../models/M2.md#c-p1)关注主体把认知资源指向哪里。

**操作入口：** [OP35](../engineering/OPERATORS.md#op35)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 确定用途；列候选特征；保留会影响本次用途的特征，并说明取舍。

**语言模式：** [LP37](../engineering/PATTERNS.md#lp37)；本接口的语境示例：“为了判断这次中断的影响，保留中断时长和恢复成本；来源也保留。颜色暂时不记录。”

**完成检查：** 能指出选了哪些、舍弃哪些及理由。

**边界与失效：** 同一事件也可产生 C-P1 注意变化；选取不代表穷尽。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

<a id="r-p2"></a>

### 特征区分（Differentiation） · R-P2

**状态变化：** 混合特征 → 可区分特征。

把疲劳、紧张、打断等写为不同表征成分。

**相邻区别：** 特征区分检查表征中是否写出了差异；[认知区分](../models/M2.md#c-p3)检查主体能否理解区别并据此作不同处理。

**操作入口：** [OP06](../engineering/OPERATORS.md#op06)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 把混在一起的成分分别命名；用一个会导致不同描述的例子检查区别。

**语言模式：** [LP06](../engineering/PATTERNS.md#lp06)；本接口的语境示例：“把疲劳、紧张和被打断分别描述：它们各有什么可辨认的迹象？”

**完成检查：** 至少能展示会导致不同描述的差异。

**边界与失效：** 描述中的区分不证明主体理解或区分正确。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

## 概念（Concept） {#concept}

<a id="r-p3"></a>

### 分类（Categorization） · R-P3

**状态变化：** 实例集合 → 类别表征。

依据明确的归类依据形成类别，如把电话和消息归为外部中断。

**相邻区别：** 分类按依据将实例组织为类别；[抽象](../models/M1.md#r-p4)提取跨实例的关系或结构。归为同类不等于已经找到共同结构。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 确定归类依据；归入实例；用边界例检查并允许暂不归类。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)；本接口的语境示例：“按是否来自外部把中断归类；突然想到别的事属于哪一类，依据是什么？”

**完成检查：** 提供正例、边界例和归类依据。

**边界与失效：** 类别不自动意味着成员具有相同原因或本质。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="r-p4"></a>

### 抽象（Abstraction） · R-P4

**状态变化：** 具体表征 → 抽象关系或结构。

提取跨实例可复用的关系，而不只是起一个更宽泛的名字。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 比较实例的关系结构；提出可复用结构；检查新例的对应及限度。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)；本接口的语境示例：“这些事件是否都有“外部输入打断当前活动”的结构？哪个例子不符合？”

**完成检查：** 在新例中能说明结构对应及不对应处。

**边界与失效：** 抽象程度按任务选择，不能把细节删光视为成功。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="r-c1"></a>

### 概念形成（Concept Formation） · R-C1

**状态变化：** 结构化材料 → 可重复调用的概念表征。

从实例、区别、属性与关系组织工作概念，并以边界和新例检查。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)、[OP35](../engineering/OPERATORS.md#op35)、[OP06](../engineering/OPERATORS.md#op06)、[OP36](../engineering/OPERATORS.md#op36)。需要组织完整任务时参照[PR01](../engineering/PROTOCOLS.md#pr01)；按缺口组合，已有状态复用。

**怎样做：** 围绕用途选特征、区别和类别；组织定义；用正例、反例和新例检查。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)、[LP37](../engineering/PATTERNS.md#lp37)、[LP06](../engineering/PATTERNS.md#lp06)、[LP38](../engineering/PATTERNS.md#lp38)；本接口的语境示例：“这里的“外部中断”指什么？给一个属于、一个不属于和一个边界例。”

**完成检查：** 能定义、举例、识别边界，并在新例调用。

**边界与失效：** 一次命名只是暂定概念，不足以证明长期稳定或掌握。

**可复用组成：** [R-P1](../models/M1.md#r-p1)、[R-P2](../models/M1.md#r-p2)、[R-P3](../models/M1.md#r-p3)、[R-P4](../models/M1.md#r-p4)、[R-P5](../models/M1.md#r-p5)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME03](../MECHANISMS.md#me03)。

## 表达（Expression） {#expression}

<a id="r-p5"></a>

### 语言编码（Linguistic Encoding） · R-P5

**状态变化：** 待表达内容 → 语言表征。

把概念、经验、关系或认知内容编码为可供解释的语言表征；接收者是否理解另作检查。

**相邻区别：** 语言编码检查含义是否得到表达；[共享核验](../models/M3.md#i-p1)另查接收者对指定内容是否有足够理解依据。

**操作入口：** [OP36](../engineering/OPERATORS.md#op36)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 确定要表达的含义与对象；写出语言表征；核对关键条件、来源和未知。

**语言模式：** [LP38](../engineering/PATTERNS.md#lp38)；本接口的语境示例：“我想表达的是“消息打断了阅读”，不是“消息导致我考试失败”；后者目前没有依据。”

**完成检查：** 主体能确认关键含义得到表达；来源和未知未丢失。

**边界与失效：** 知道想法和表达准确是两件事；表达影响接收者进入 Bridge。

**机制候选：** [ME03](../MECHANISMS.md#me03)。

<a id="r-p6"></a>

### 压缩（Compression） · R-P6

**状态变化：** 详细表征 → 压缩表征。

在保留任务相关信息的条件下总结或命名。

**相邻区别：** 压缩减少表达细节，[展开](../models/M1.md#r-p7)增加可辨认的细节；展开不能自动恢复压缩时丢失的材料。

**操作入口：** [OP33](../engineering/OPERATORS.md#op33)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 确定摘要用途；保留关键关系与条件；标出省略及可回查材料。

**语言模式：** [LP33](../engineering/PATTERNS.md#lp33)；本接口的语境示例：“把讨论压成三点，保留仍有争议的条件和来源，细节放在原记录。”

**完成检查：** 说明总结保留什么、省略什么，重要材料可追溯。

**边界与失效：** 短不等于准确；不能无声改变量词、因果和责任。

**机制候选：** [ME03](../MECHANISMS.md#me03)。

<a id="r-p7"></a>

### 展开（Expansion） · R-P7

**状态变化：** 压缩表征 → 展开的属性、事实或关系。

把“项目失败”展开为技术、进度、用户和商业维度。

**操作入口：** [OP33](../engineering/OPERATORS.md#op33)、[OP09](../engineering/OPERATORS.md#op09)。只处理当前缺口，多个入口按前提选择。

**怎样做：** 定位压缩标签；按用途展开维度；区分来源内容与新生成待查项。

**语言模式：** [LP33](../engineering/PATTERNS.md#lp33)、[LP09](../engineering/PATTERNS.md#lp09)；本接口的语境示例：““项目失败”具体指交付、使用效果还是成本？目前哪些有材料，哪些待查？”

**完成检查：** 区分原始材料、解释和新生成的待查细节。

**边界与失效：** 不是无损解压；无来源细节不能补写成事实。

**机制候选：** [ME03](../MECHANISMS.md#me03)。
