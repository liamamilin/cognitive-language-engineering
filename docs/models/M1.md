# M1. Representation State Model｜表征状态模型

版本 v0.7 · 完整体系发布稿。

观察表征结构及其转换。经验、特征、类别、概念与语言形式是可往复组织的网络，不是必须逐项走完的流水线。

表征变化与主体认知变化可同时发生；M1 记录表示了什么，M2 记录主体能识别或使用什么。

本模型登记 9 个接口：7 个 P 编号、2 个 Composite。P 表示当前工程粒度，不是心理机制不可再分的证明。

**接口组织：** 本模型按所指（Referent）、特征（Feature）、概念（Concept）、表达（Expression）组织接口。所指说明名称或描述具体指向什么对象；特征说明从哪些方面描述和区分对象；概念说明怎样依据特征或关系归类、抽象并组织可复用含义；表达说明怎样用语言呈现这些内容。

明确所指后，特征有了清楚的归属。例如，讨论页面整体与讨论标题、正文的排列方式，需要保留的描述方面可能不同。特征为概念提供候选依据，但还需要说明归类依据、含义和边界；表达再将这些内容写清，并核对来源和未知。压缩或展开会调整细节，也可能遗漏或增添含义。

这个顺序帮助读者进入体系。实际处理可以往复：少量特征可以帮助指认对象，后续判断也可能要求修正名称或范围；已有明确对象时直接复用。

## 使用约定

语言模式用于把算子落实为语言操作，指向本接口的变化。每项先给一条可直接背诵的核心句，再给展开：核心句提示操作方向；展开是可直接填入内容、用于自问或交流的表达，写清对什么做什么。完成检查另说明怎样判断结果。〔……〕是待填位置；对象也可由前文提供。按缺口选用必要展开，已有状态可复用；一个模式不必独自完成复合接口，也不要求同时使用全部链接。是否发生变化仍看完成检查，不能凭说出核心句判定。

操作入口列出可选方法；按当前缺口和方法前提选择，不要求逐项调用。需要组织完整任务时再参考协议；仍然有效的已有状态直接复用。

条目机制映射均为工程解释候选；针对此目标的 CLE 干预效果默认 E0，即尚无该效果主张的验证；工程定义被采用与效果验证是两件事。Composite 的“组成”列表示可复用过程，不规定全部必经；已有输入直接复用。失败、无变化与信息不足都须保留。

卡片箭头写接口的变化方向；本次是否具备前状态、是否发生变化，须另用材料判断。没有前状态时先检查当前情况，不倒推此前“没有”或“不会”。详见[状态与变化](../STATE_SPEC.md)。

## 所指（Referent） {#referent}

所指是名称或描述在当前材料中具体指向的对象或内容。先分清材料、对象和名称：材料是拿来分析的信息，如截图、记录或回忆；对象是本次要讨论的内容，可以是事物、经历、现象或关系；名称是用来称呼它的词。材料整体不一定就是本次对象。

例如，面对一张页面截图，“页面”可以指界面整体；“文字排版”可以指标题与正文的字号、间距和排列。若讨论内容如何组织、怎样引导阅读，本例暂用“信息呈现设计”称呼这一主题。三个称呼涉及不同讨论范围，要按当前关注的问题说明所指。这里是构造示范，不规定材料只有一个正确名称。

“回查”就是能根据这份表达回到材料找到它们；材料是自述或回忆时，保留相应来源和未知。详见[表征术语](../GLOSSARY.md#representation-terms)。

<a id="r-c2"></a>

### 指认（Identification） · R-C2

**状态变化：** 讨论所指尚未明确 → 有明确所指、可以回查的对象表征。

从材料中明确本次讨论的对象，用名称或描述建立可以回查的指代，也就是让称呼能对应到具体内容。不要求先找到正式术语。

**相邻区别：** 指认回答“讨论什么”，[特征选择](#r-p1)回答“按当前用途保留哪些描述方面”。指认可以借用少量特征定位对象；例如“页面里字号最大的那段文字”借字号定位所指，之后分析可读性时再选择有关特征。

[具体化](../models/M2.md#c-c1)和[边界形成](../models/M2.md#c-p13)可帮助补明所指与范围，[语言编码](#r-p5)可把它们表达出来。指认的检查重点是能否找到所指；找到名称不等于已经[形成概念](#r-c1)，主体理解与共享解释仍分别在M2、M3检查。

**操作入口：** [OP09](../engineering/OPERATORS.md#op09)、[OP10](../engineering/OPERATORS.md#op10)、[OP36](../engineering/OPERATORS.md#op36)。

**怎样做：** 按当前缺口选用必要方法。

1. 所指不清时，用OP09指出材料中的具体内容，并补一句描述。
2. 仍有歧义时，用OP10说明包括与不包括什么；范围已清楚就跳过。
3. 用OP36写出合适的名称或描述，再回到材料确认它指什么。

需要找现有术语时，再核对该术语的含义是否适合当前对象。名称不确定就保留待确认，不阻断已经可以进行的描述与分析。

**语言模式：** [LP09](../engineering/PATTERNS.md#lp09)、[LP10](../engineering/PATTERNS.md#lp10)、[LP38](../engineering/PATTERNS.md#lp38)。

**核心句：** “指出我们讨论的是什么，给它一个明确的称呼。”

**展开：** “就〔当前关注的问题或用途〕而言，〔材料〕中我们具体讨论什么？请指出有关部分，用一句话描述。它有合适的名称吗？不知道时先保留描述，名称待确认；仍有歧义，再说明包括和不包括什么。”

**完成检查：** 能根据名称或描述回到材料找到所指；名称尚不确定时，明确保留待确认。

例如，已经明确指向整张截图时，“这张图”可以够用；若本次只讨论其中的文字排列，就需要补明这一范围。称呼是否足够取决于当前材料、前文和用途，而不是词有多专业。

**边界与失效：** 名称不能替代所指，也不证明归类、事实或解释正确。范围随用途和情境调整；自述或回忆仍保留来源与未知。已有明确所指时直接复用。

**可复用组成：** [R-P5](../models/M1.md#r-p5)。

**跨域过程引用：** [C-C1](../models/M2.md#c-c1)、[C-P13](../models/M2.md#c-p13)。

语言编码是可复用的表征过程；具体化与边界形成是按缺口借用的跨域过程。这些联系不规定全部必经，也不自动登记认知变化。

## 特征（Feature） {#feature}

这里的特征指对象或经验中可以辨认和描述的某个方面，包括属性、状态或表现。“中断时长”是描述方面，“3分钟”是它的具体取值；时长也可以未知。任务决定哪些方面值得保留，不决定它是否属于特征。特征不专指显著、独特或本质的性质。

例如，描述一次阅读中断，可以保留来源、时长、恢复时间。中断事件是被描述的对象；这些方面是描述它的特征；日志和自述是信息来源。三者分别记录。详见[表征术语](../GLOSSARY.md#representation-terms)。

<a id="r-p1"></a>

### 特征选择（Feature Selection） · R-P1

**状态变化：** 未组织的任务相关经验 → 已选择特征。

为了当前用途，决定从哪些方面描述对象或经验，并保留这些方面的有关信息。例如判断中断影响时保留中断时长和恢复时间；尚未取得的取值标为未知。“未组织”仅指当前用途下尚未明确怎样描述。

**相邻区别：** 特征选择决定表征保留哪些内容；[聚焦](../models/M2.md#c-p1)关注主体把认知资源指向哪里。

**操作入口：** [OP35](../engineering/OPERATORS.md#op35)。

**怎样做：** 确定用途；对象所指未明时用[指认](#r-c2)补明；列候选特征，保留会影响本次用途的方面，并说明取舍。

**语言模式：** [LP37](../engineering/PATTERNS.md#lp37)。

**核心句：** “按用途选特征，保留取值和依据。”

**展开：** “为了〔用途〕，〔对象〕可以从哪些方面描述？哪些方面会改变本次判断？请列出保留的特征、取值或未知及来源，再说明暂时舍弃其他方面的理由。”

**完成检查：** 能指出选了哪些、舍弃哪些及理由。

例如，用所选特征判断一次任务能否开始时，能说明每项特征怎样影响判断；取值未知仍保留未知。

**边界与失效：** 同一事件也可产生 C-P1 注意变化；选取不代表穷尽。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

<a id="r-p2"></a>

### 特征区分（Differentiation） · R-P2

**状态变化：** 混合特征 → 可区分特征。

把“工作不在状态”中混在一起的描述方面分开，例如疲劳程度、紧张程度和中断频率。疲劳与紧张是不同状态，中断是事件；它们不会因一起出现在描述中就成为同一种对象。此处区分的是工作经历的不同描述方面。

**相邻区别：** 特征区分检查表征中是否写出了差异；[认知区分](../models/M2.md#c-p3)检查主体能否理解区别并据此作不同处理。

**操作入口：** [OP06](../engineering/OPERATORS.md#op06)。

**怎样做：** 把混在一起的成分分别命名；用一个会导致不同描述的例子检查区别。

**语言模式：** [LP06](../engineering/PATTERNS.md#lp06)。

**核心句：** “把混在一起的特征分开描述。”

**展开：** “请把〔混合描述〕中的不同方面分别命名，写出各自取值及依据。用〔对照实例〕说明：合在一个词里会遗漏哪些区别？”

**完成检查：** 至少能展示会导致不同描述的差异。

例如，将“工作不在状态”分成疲劳程度、紧张程度和中断频率；这些方面可以相关，不要求相互独立。

**边界与失效：** 描述中的区分不证明主体理解或区分正确。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

## 概念（Concept） {#concept}

概念是用来识别、区分和理解一类对象或关系的可复用含义；类别是按归类依据划出的实例范围；名称是指称它们的词。例如，“外部中断”的含义要说明哪些情况算、哪些不算，有关事件才可按这一依据归类。抽象则从实例中提取可复用关系或结构，不只是给类别换一个更大的名字。

用同一组构造材料看区别：甲因接听来电停止阅读，乙因响应敲门停止写作，丙收到消息但继续阅读。选择“输入来源”和“当前活动是否被打断”两个特征后，仍需确定归类依据。本例暂把“外部输入使当前活动停止或切换”定义为外部中断；甲、乙可归入，丙不归入。分类得到的是哪些实例属于这一类；抽象提取的是甲、乙共有的关系“外部输入 → 活动停止或切换”，电话与敲门、阅读与写作分别对应。把这项含义写清，并说明丙为什么不属于，才有可继续检查的概念表征。新例是否适用仍要核对，不能从三个例子宣称找到了中断的普遍本质。

<a id="r-p3"></a>

### 分类（Categorization） · R-P3

**状态变化：** 实例集合 → 类别表征。

按明确的归类依据形成类别。例如，把因接听来电或回应消息而中断当前活动的事件归为外部中断；仅收到消息而未中断的情况不归入。

**相邻区别：** 分类按依据将实例组织为类别；[抽象](../models/M1.md#r-p4)提取跨实例的关系或结构。归为同类不等于已经找到共同结构。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)。

**怎样做：** 确定归类依据；归入实例；用边界例检查并允许暂不归类。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)。

**核心句：** “先定归类依据，再把实例归入类别。”

**展开：** “为了〔用途〕，先写明〔实例集合〕的归类依据，再逐个说明归入哪一类及理由。哪些正例、反例或边界例提示依据需要修改？材料不足的实例先留待判断。”

**完成检查：** 提供正例、边界例和归类依据。

**边界与失效：** 类别不自动意味着成员具有相同原因或本质。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="r-p4"></a>

### 抽象（Abstraction） · R-P4

**状态变化：** 具体表征 → 抽象关系或结构。

提取跨实例可复用的关系，而不只是起一个更宽泛的名字。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)。

**怎样做：** 比较实例的关系结构；提出可复用结构；检查新例的对应及限度。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)。

**核心句：** “提取跨实例的结构，再检查新例的对应。”

**展开：** “比较〔实例〕中各要素怎样联系，写出可复用的〔候选关系或结构〕及各部分的对应。换一个新例，哪些关系仍对应，哪些不对应？据此调整适用范围。”

**完成检查：** 在新例中能说明结构对应及不对应处。

**边界与失效：** 抽象程度按任务选择，不能把细节删光视为成功。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="r-c1"></a>

### 概念形成（Concept Formation） · R-C1

**状态变化：** 结构化材料 → 可重复调用的概念表征。

从实例、区别、属性与关系组织工作概念，并以边界和新例检查。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)、[OP35](../engineering/OPERATORS.md#op35)、[OP06](../engineering/OPERATORS.md#op06)、[OP36](../engineering/OPERATORS.md#op36)。完整任务可参照[PR01](../engineering/PROTOCOLS.md#pr01)。

**怎样做：** 围绕用途选特征、区别和类别；组织定义；用正例、反例和新例检查。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)、[LP37](../engineering/PATTERNS.md#lp37)、[LP06](../engineering/PATTERNS.md#lp06)、[LP38](../engineering/PATTERNS.md#lp38)。

**核心句：** “从材料形成定义，用新例检验。”

**展开：** “为了〔用途〕，比较〔实例材料〕：哪些特征或关系可以作为归类依据？据此，暂把〔名称〕定义为〔含义〕，说明为什么包括〔正例〕、排除〔反例〕。换一个新例，这个定义还能帮助判断吗？哪里需要补材料或修改定义？”

**完成检查：** 能定义、举例、识别边界，并在新例调用。

换一个未讨论过的实例，按定义判断归入、不归入或暂时无法判断，并说明理由。仅命名不算形成可复用含义；材料不足与定义边界不清分别说明。

**边界与失效：** 一次命名只是暂定概念，不足以证明长期稳定或掌握。

这里“暂定概念”指仍待补明含义和检验的候选，不表示仅凭起名就形成了概念。指认对象所用的称呼也不必承担概念定义。

**可复用组成：** [R-P1](../models/M1.md#r-p1)、[R-P2](../models/M1.md#r-p2)、[R-P3](../models/M1.md#r-p3)、[R-P4](../models/M1.md#r-p4)、[R-P5](../models/M1.md#r-p5)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME03](../MECHANISMS.md#me03)。

## 表达（Expression） {#expression}

表征是对内容的表示；语言表征是用词句等语言形式作出的表示。表达组织这种形式，编码说明怎样将待表达内容写出来。压缩与展开调整细节程度，也就是本文所说的“分辨率”；它们都须保留来源，细节多不自动更准确。

<a id="r-p5"></a>

### 语言编码（Linguistic Encoding） · R-P5

**状态变化：** 待表达内容 → 语言表征。

把概念、经验、关系或认知内容编码为可供解释的语言表征；接收者是否理解另作检查。

**相邻区别：** 语言编码检查含义是否得到表达；[共享核验](../models/M3.md#i-p1)另查接收者对指定内容是否有足够理解依据。

**操作入口：** [OP36](../engineering/OPERATORS.md#op36)。

**怎样做：** 确定要表达的含义与对象；写出语言表征；核对关键条件、来源和未知。

**语言模式：** [LP38](../engineering/PATTERNS.md#lp38)。

**核心句：** “把要表达的内容写出来，再核对原意。”

**展开：** “请把〔待表达内容〕写成适合〔接收对象与用途〕的表达，保留关键关系、条件、来源和未知。对照原材料，哪些含义保留了，哪些遗漏或被增添？请作必要修改。”

**完成检查：** 主体能确认关键含义得到表达；来源和未知未丢失。

需要主体确认原意时取得相应反馈；表达准确、事实正确和接收者理解分别检查。

**边界与失效：** 知道想法和表达准确是两件事；表达影响接收者进入 Bridge。

**机制候选：** [ME03](../MECHANISMS.md#me03)。

<a id="r-p6"></a>

### 压缩（Compression） · R-P6

**状态变化：** 详细表征 → 压缩表征。

在保留任务相关信息的条件下总结或命名。

这里的命名用简短标签代替较详细的表示。若当前缺口是名称具体指什么，按[指认](#r-c2)检查；不凭名称短就登记发生压缩。

**相邻区别：** 压缩减少表达细节，[展开](../models/M1.md#r-p7)增加可辨认的细节；展开不能自动恢复压缩时丢失的材料。

**操作入口：** [OP33](../engineering/OPERATORS.md#op33)。

**怎样做：** 确定摘要用途；保留关键关系与条件；标出省略及可回查材料。

**语言模式：** [LP33](../engineering/PATTERNS.md#lp33)。

**核心句：** “压缩材料，保留关键区别与回查入口。”

**展开：** “为了〔用途〕，请把〔原材料〕整理成〔摘要形式〕，保留会影响判断的区别、关系和条件。说明省略了什么、详细材料在哪里，再对照原材料核对摘要。”

**完成检查：** 说明总结保留什么、省略什么，重要材料可追溯。

**边界与失效：** 短不等于准确；不能无声改变量词、因果和责任。

**机制候选：** [ME03](../MECHANISMS.md#me03)。

<a id="r-p7"></a>

### 展开（Expansion） · R-P7

**状态变化：** 压缩表征 → 展开的属性、事实或关系。

“项目失败”没有说明失败在哪一方面。可以按当前用途追问交付是否完成、使用结果是否满足期待、成本是否超出条件。这些是候选检查方面；只有取得材料后，才能说本项目在哪一方面出了问题。

**操作入口：** [OP33](../engineering/OPERATORS.md#op33)、[OP09](../engineering/OPERATORS.md#op09)。

**怎样做：** 定位压缩标签；按用途展开维度；区分来源内容与新生成待查项。

**语言模式：** [LP33](../engineering/PATTERNS.md#lp33)、[LP09](../engineering/PATTERNS.md#lp09)。

**核心句：** “展开这个标签，把来源与待查项分开。”

**展开：** “〔压缩说法〕具体包含哪些事实、属性或关系？请按〔用途〕展开，注明哪些有原材料支持、哪些是解释、哪些是新想到的待查项；缺少的材料从哪里取得？”

**完成检查：** 区分原始材料、解释和新生成的待查细节。

展开出的细节不能自动当作原材料中已有的内容，也不能据此声称恢复了压缩时丢失的信息。

**边界与失效：** 不是无损解压；无来源细节不能补写成事实。

**机制候选：** [ME03](../MECHANISMS.md#me03)。
