# M3. Shared Cognition & Interaction State Model｜共享认知与互动状态模型

版本 v0.7 · 完整体系发布稿。

观察主体间信息、解释、模型、框架、分歧和共同背景。共享始终有对象、范围和确认依据。

共同信息（Shared Information）、共同含义（Shared Meaning）、共同模型（Shared Model）、共同框架（Shared Frame）与同意（Agreement）分别记录。共享解释可以错误；准确理解可伴随持续分歧。

本模型登记 9 个接口：1 个 P 编号、8 个 Composite。P 表示当前工程粒度，不是心理机制不可再分的证明。

**接口组织：** 本模型按信息（Information）、对齐（Alignment）、分歧（Disagreement）、背景（Common Ground）组织接口。信息提供各方共同讨论的材料；对齐围绕这些信息，协调各方对含义、系统模型和工作框架的理解。对齐可以帮助定位分歧，分歧则说明各方究竟在哪些判断上不同；即使理解一致，分歧也可能继续存在。

新信息、对齐后的含义，以及分歧处理中确认的共同部分和未决部分，都可以更新背景；背景又为后续信息的解释和对齐提供共同参照。因此，背景持续连接前后的互动，也会在没有分歧时更新。

例如，两人先确认都取得同一稿件，这是信息范围；再约定本次“完成”指已验收，这是含义对齐。两人仍可分别认为应周五或周一交付，这是期限选择的分歧。若双方确认已理解上述共同含义和保留分歧，后续可据此继续讨论，这些确认内容才可纳入背景。共用文件提供讨论材料；相互反馈提供可共同调用的依据。只有共用文件，还不能确认上述内容已经成为共同背景。

## 使用约定

操作入口列出可选方法；按当前缺口和方法前提选择，不要求逐项调用。需要组织完整任务时再参考协议；仍然有效的已有状态直接复用。

条目机制映射均为工程解释候选；针对此目标的 CLE 干预效果默认 E0，即尚无该效果主张的验证；工程定义被采用与效果验证是两件事。Composite 的“组成”列表示可复用过程，不规定全部必经；已有输入直接复用。失败、无变化与信息不足都须保留。

卡片箭头写接口的变化方向；本次是否具备前状态、是否发生变化，须另用材料判断。没有前状态时先检查当前情况，不倒推此前“没有”或“不会”。详见[状态与变化](../STATE_SPEC.md)。

## 信息（Information） {#information}

信息是任务有关的内容和材料；共同信息说明各方取得或可调用同一范围的材料。理解则看主体能否解释、辨认或处理有关内容，不能仅凭文件存在判断。共享核验取得局部依据，并不要求知道彼此所有想法。

<a id="i-c1"></a>

### 共同信息形成（Shared Information Formation） · I-C1

**状态变化：** 信息不对称 → 相关主体获得任务所需共同信息。

传递相关材料并确认接收和可调用程度。

**相邻区别：** 共同信息形成关注各方获得同一范围的材料；[共享核验](../models/M3.md#i-p1)检查共享已有多少依据，材料存在不等于已被理解。

**操作入口：** [OP23](../engineering/OPERATORS.md#op23)、[OP36](../engineering/OPERATORS.md#op36)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。

**怎样做：** 传递同版本材料；确认已接收且能调用；明确缺项和来源。

**语言模式：** [LP23](../engineering/PATTERNS.md#lp23)、[LP38](../engineering/PATTERNS.md#lp38)；本接口的语境示例：“我们都在看这份修订稿吗？请指出当前版本和你尚未拿到的材料。”

**完成检查：** 主体可引用同一版本材料，关键缺项和来源明确。

**边界与失效：** 共同持有与共同知道彼此持有不同；B-C2 是传递与互动的跨域过程引用，不是必须先完整完成的子步骤。

**可复用组成：** [I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME11](../MECHANISMS.md#me11)。

<a id="i-p1"></a>

### 共享核验（Sharedness Verification） · I-P1

**状态变化：** 假定共享 → 对指定内容具有足够确认依据。

按任务需要，用复述、新例、预测或操作反馈检查共享范围。

检查方式要对应所求：复述可帮助发现听错对象或条件；新例可看对方是否会应用同一区别；操作反馈可看是否按约定处理。它们各自取得局部迹象，不是一种方式通过就代表其他方面全部成立。例如，能复述“验收后才完成”，还需另查面对“仅提交”的新例时怎样判断。

**操作入口：** [OP23](../engineering/OPERATORS.md#op23)。

**怎样做：** 确定需共享内容；取得复述、新例、预测或操作反馈；限定确认范围。

**语言模式：** [LP23](../engineering/PATTERNS.md#lp23)；本接口的语境示例：“请用自己的方式说明这一点，并判断一个新例；还有哪些部分未检查？”

**完成检查：** 记录检查内容、方式和残余不确定性。

**边界与失效：** Verified Shared 的旧表述改为有范围的确认；复述不证明完全理解或事实真实。

**机制候选：** [ME10](../MECHANISMS.md#me10)。

## 对齐（Alignment） {#alignment}

含义说明表达指什么；系统模型说明有关实体、关系和过程怎样组织；框架说明本轮处理什么范围、按什么视角看。共同采用这些内容是对应的对齐。此处系统模型与CLE四模型有别：前者描述具体系统，后者组织观察视角。理解对方说什么，与同意该说法分别判断。

以“提交文档”为例：把“提交”解释为文件已传到指定位置，是含义；说明“上传后进入审核，审核后通知提交者”，是系统模型；约定本轮只讨论是否送达，是框架。含义对齐后仍可能对审核流程的模型不同，框架相同也不保证系统模型相同。因此三种对齐需要分别说明共同采用了什么。

<a id="i-c2"></a>

### 澄清（Clarification） · I-C2

**状态变化：** 表达的多种未决解释 → 任务所需澄清。

明确歧义点、对象、例子、反例与条件。

**相邻区别：** 澄清缩小具体表达的未决解释；[含义对齐](../models/M3.md#i-c3)使双方在指定范围共同采用足够一致的解释。

**操作入口：** [OP24](../engineering/OPERATORS.md#op24)、[OP09](../engineering/OPERATORS.md#op09)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。

**怎样做：** 定位未决解释；比较对象、例子与条件；检查相关情境中的所指。

**语言模式：** [LP24](../engineering/PATTERNS.md#lp24)、[LP09](../engineering/PATTERNS.md#lp09)；本接口的语境示例：“你说‘完成’指已提交还是已验收？分别给一个例子。”

**完成检查：** 对相关具体情境可一致判定所指。

**边界与失效：** 澄清是局部缩小歧义，不保证双方对所有方面一致。

**可复用组成：** [C-P3](../models/M2.md#c-p3)、[C-C1](../models/M2.md#c-c1)、[I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME11](../MECHANISMS.md#me11)。

<a id="i-c3"></a>

### 含义对齐（Meaning Alignment） · I-C3

**状态变化：** 不同解释 → 足够一致的解释。

比较各自主张含义，修正差异，并检查边界例。

**相邻区别：** 含义对齐关注表达怎样理解；[模型对齐](../models/M3.md#i-c4)关注实体、关系与预测，[框架对齐](../models/M3.md#i-c5)关注本次讨论的范围与视角。

**操作入口：** [OP24](../engineering/OPERATORS.md#op24)、[OP23](../engineering/OPERATORS.md#op23)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。

**怎样做：** 各自说明含义；约定本次工作解释；检查边界及未约定部分。

**语言模式：** [LP24](../engineering/PATTERNS.md#lp24)、[LP23](../engineering/PATTERNS.md#lp23)；本接口的语境示例：“本次我们共同采用‘已验收’的含义；它不包括仅上传文件，对吗？”

**完成检查：** 双方能准确说明约定含义及未约定部分。

**边界与失效：** 理解一致不代表观点相同、标准相同或承担任务。

**可复用组成：** [I-C2](../models/M3.md#i-c2)、[I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME11](../MECHANISMS.md#me11)。

<a id="i-c4"></a>

### 模型对齐（Model Alignment） · I-C4

**状态变化：** 不同系统模型 → 任务所需的共同模型。

对实体、关系、边界与候选过程形成可检验的共同结构。

**操作入口：** [OP24](../engineering/OPERATORS.md#op24)、[OP34](../engineering/OPERATORS.md#op34)、[OP23](../engineering/OPERATORS.md#op23)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。

**怎样做：** 共同列实体、关系和边界；比较同一变化的预测；确认共同采用范围。

**语言模式：** [LP24](../engineering/PATTERNS.md#lp24)、[LP34](../engineering/PATTERNS.md#lp34)、[LP23](../engineering/PATTERNS.md#lp23)；本接口的语境示例：“我们各自认为输入A怎样影响B？在本次范围内共同采用哪种结构，怎样检查？”

**完成检查：** 在约定范围共同采用同一结构，并能说明同一变化的预测；范围外差异另记。若仍有范围内模型冲突，只记录部分对齐或未达成。

**边界与失效：** 模型可共同错误；无需所有背景知识完全一致。

**可复用组成：** [I-C1](../models/M3.md#i-c1)、[I-C3](../models/M3.md#i-c3)、[I-P1](../models/M3.md#i-p1)、[C-P14](../models/M2.md#c-p14)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME10](../MECHANISMS.md#me10)。

<a id="i-c5"></a>

### 框架对齐（Frame Alignment） · I-C5

**状态变化：** 不同问题范围／视角 → 共同工作框架。

协调本次讨论对象、目的、边界和分析维度。

**操作入口：** [OP24](../engineering/OPERATORS.md#op24)、[OP10](../engineering/OPERATORS.md#op10)、[OP23](../engineering/OPERATORS.md#op23)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。

**怎样做：** 明确本次对象、目的和维度；约定工作框架；保留其他框架。

**语言模式：** [LP24](../engineering/PATTERNS.md#lp24)、[LP10](../engineering/PATTERNS.md#lp10)、[LP23](../engineering/PATTERNS.md#lp23)；本接口的语境示例：“本轮只讨论能否开始执行，结果收益另查；这是否是我们共同的讨论范围？”

**完成检查：** 能说明当前处理什么，以及保留哪些其他框架。

**边界与失效：** 框架共同使用不代表真实原因已被确定。

**可复用组成：** [I-C3](../models/M3.md#i-c3)、[C-P13](../models/M2.md#c-p13)、[I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME11](../MECHANISMS.md#me11)。

## 分歧（Disagreement） {#disagreement}

分歧是各方在事实、解释、价值、标准或选择上的不一致。同意表示赞成某内容，准确理解仍可以伴随反对。结果状态在这里指讨论当前达成一致、保留分歧或暂停的情况，不能自动当作社会承诺或现实行动结果。

<a id="i-c6"></a>

### 分歧组织（Disagreement Structuring） · I-C6

**状态变化：** 笼统不一致 → 可定位的分歧。

区分事实、含义、证据、模型、价值、标准和行动选择差异。

**相邻区别：** 分歧组织定位各方不同在哪里；[结果状态形成](../models/M3.md#i-c7)确认一致、保留分歧或暂停等当前结果。

**操作入口：** [OP25](../engineering/OPERATORS.md#op25)、[OP24](../engineering/OPERATORS.md#op24)、[OP13](../engineering/OPERATORS.md#op13)。完整任务可参照[PR08](../engineering/PROTOCOLS.md#pr08)。

**怎样做：** 表达并确认双方立场；把冲突绑定事实、含义、模型、标准或行动；标共享处。

**语言模式：** [LP25](../engineering/PATTERNS.md#lp25)、[LP24](../engineering/PATTERNS.md#lp24)、[LP13](../engineering/PATTERNS.md#lp13)；本接口的语境示例：“我们是在争来源可靠性，还是同样材料下的成本取舍？”

**完成检查：** 每个分歧绑定对象与双方立场，并标共享部分。

**边界与失效：** 结构化不必消除分歧，不把强势者的说法当共同判断。

**可复用组成：** [I-C2](../models/M3.md#i-c2)、[C-P3](../models/M2.md#c-p3)、[C-P19](../models/M2.md#c-p19)、[I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME11](../MECHANISMS.md#me11)。

<a id="i-c7"></a>

### 结果状态形成（Resolution State Formation） · I-C7

**状态变化：** 已定位分歧 → 一致、明确保留分歧或暂停。

确定哪些结论被接受、哪些待查、何时重开讨论。

**操作入口：** [OP25](../engineering/OPERATORS.md#op25)、[OP23](../engineering/OPERATORS.md#op23)。完整任务可参照[PR08](../engineering/PROTOCOLS.md#pr08)。

**怎样做：** 在已定位分歧上确认一致、保留分歧或暂停；说明范围及重开条件。

**语言模式：** [LP25](../engineering/PATTERNS.md#lp25)、[LP23](../engineering/PATTERNS.md#lp23)；本接口的语境示例：“这一点仍不同意；我们先记录双方依据，取得新材料后再讨论，可以吗？”

**完成检查：** 参与者确认结果状态及其范围，允许不一致。

**边界与失效：** M3 的认可不同于 M4 承诺；沉默和疲倦不自动算同意。

**可复用组成：** [I-C6](../models/M3.md#i-c6)、[I-P1](../models/M3.md#i-p1)。

**跨域过程引用：** [B-C2](../BRIDGES.md#b-c2)。

**机制候选：** [ME10](../MECHANISMS.md#me10)。

## 背景（Common Ground） {#common-ground}

共同背景是各方有理由互认为后续可共同调用的信息、含义或约定，例如已确认的工作解释与版本。共同持有材料只是条件之一；还须有互相可调用的依据。共享确认（grounding）是取得这些局部理解依据的互动过程，背景是后续互动可利用的内容，两者不是同一个对象。

例如，甲指明使用稿件版本二，乙回应能找到同一版本并按本次约定解释“完成”，甲据此确认后续讨论沿用这项解释。这些反馈为双方共同调用提供局部依据；如果乙没有回应，甲只能记录已提供材料，不能补写乙已读懂。双方还可以共同记下“期限仍有分歧”；共同知道有分歧，并不等于对期限已经同意。

<a id="i-c8"></a>

### 共同背景更新（Common-Ground Updating） · I-C8

**状态变化：** 旧共同背景 → 更新且带状态的共同背景。

纳入新信息、含义、决定；撤回失效假设并记录版本。

**相邻区别：** 共同背景更新纳入信息、含义与结果的变化；[结果状态形成](../models/M3.md#i-c7)只关注分歧处理的结果状态。背景也可在没有分歧时更新。

**操作入口：** [OP23](../engineering/OPERATORS.md#op23)、[OP25](../engineering/OPERATORS.md#op25)、[OP24](../engineering/OPERATORS.md#op24)。完整任务可参照[PR07](../engineering/PROTOCOLS.md#pr07)。
