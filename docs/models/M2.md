# M2. Individual Cognitive State Model｜个体认知状态模型

版本 v0.7 · 完整体系发布稿。

观察注意、理解、搜索、假设、评价、目标、选择和规划状态。认知状态只能根据任务相关迹象推断，不能直接从流畅回答认定改变。

自我目标采纳、计划和实施意图（“如果出现某线索，就采取某动作”的绑定）保持在 M2；实际建立他人任务、义务或权限进入 M4。

本模型登记 35 个接口：21 个 P 编号、14 个 Composite。P 表示当前工程粒度，不是心理机制不可再分的证明。

**接口组织：** 本模型以对象（Object）、关系（Relation）、问题（Problem）、目标（Goal）、决策（Decision）、计划（Plan）、反思（Reflection）组织接口。对象是认知所指向的内容，关系将对象连接为可以比较和理解的结构；围绕对象及其关系，可以形成需要解释或解决的问题。

目标表达主体采纳并愿意追求的期望状态，为相关问题的处理提供方向。决策针对问题或目标，依据适用标准与材料评价候选并形成选择；计划将已采纳的目标或选择组织为实现路径。

反思回看对象的界定、关系与解释的依据，以及目标、决策和计划中的未知与局限，帮助主体判断哪些内容应保留、哪些需要修正。

例如，先把“读不下去”的对象限定为一次阅读经历；关系组可比较这次与另一次的中断、恢复情况；问题组追问究竟要解释恢复慢，还是要解决无法继续。希望减少恢复时间属于期望，本人准备追求它才进入已采纳目标。决策比较暂停提醒等候选，计划说明下一次怎样尝试；反思则核对恢复时间有没有记录、判断是不是仅凭回忆。前一句为后一句提供对象或条件，仍不足以直接推出后一句的结论。已有目标时也可直接从该处阅读，不必先重建问题。

## 使用约定

语言模式用于把算子落实为语言操作，指向本接口的变化。每项先给一条可直接背诵的核心句，再给展开：核心句提示要做的操作，展开说明对什么材料怎样处理、得到什么及怎样检查。〔……〕是待填位置；对象也可由前文提供。按缺口选用必要展开，已有状态可复用；一个模式不必独自完成复合接口，也不要求同时使用全部链接。是否发生变化仍看完成检查，不能凭说出核心句判定。

操作入口列出可选方法；按当前缺口和方法前提选择，不要求逐项调用。需要组织完整任务时再参考协议；仍然有效的已有状态直接复用。

条目机制映射均为工程解释候选；针对此目标的 CLE 干预效果默认 E0，即尚无该效果主张的验证；工程定义被采用与效果验证是两件事。Composite 的“组成”列表示可复用过程，不规定全部必经；已有输入直接复用。失败、无变化与信息不足都须保留。

卡片箭头写接口的变化方向；本次是否具备前状态、是否发生变化，须另用材料判断。没有前状态时先检查当前情况，不倒推此前“没有”或“不会”。详见[状态与变化](../STATE_SPEC.md)。

## 对象（Object） {#object}

对象是当前被注意、识别或判断的内容，可以是事物、经历、方案或一句主张。认知资源统称此次可投入的注意、时间和处理能力等条件。显化使内容变得可辨认；区分辨认不同内容；边界划定范围；具体化补上影响当前判断的必要条件。

<a id="c-p1"></a>

### 聚焦（Focus） · C-P1

**状态变化：** 分散的任务关注 → 对目标对象聚焦。

把当前认知资源指向一个可辨认对象。

**操作入口：** [OP35](../engineering/OPERATORS.md#op35)。

**怎样做：** 指定当前对象和要回答的一项问题；请主体处理一份相关材料或作一项有关判断；检查其后续处理是否仍围绕这个对象。只写“我要聚焦”还不足以说明已经做到了。

**语言模式：** [LP37](../engineering/PATTERNS.md#lp37)。

**核心句：** “现在围绕这个对象处理这一项问题。”

**展开：** “为〔当前任务〕，请先关注〔对象〕并回答〔这一项问题〕，处理〔相关材料〕或作一个有关判断。随后检查你的处理是否仍围绕这个对象；偏离时再回到当前问题。”

**完成检查：** 能指出当前关注对象及其与任务的关系。

**边界与失效：** 更聚焦可能遗漏其他关键对象；不代表注意机制全被测得。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

<a id="c-p2"></a>

### 显化（Explication） · C-P2

**状态变化：** 隐含或未被识别内容 → 主体可识别内容。

主体明确意识到某个已有判断、倾向或前提。

**操作入口：** [OP09](../engineering/OPERATORS.md#op09)、[OP22](../engineering/OPERATORS.md#op22)。

**怎样做：** 请主体表达当前判断或倾向；用例子帮助辨认；核对来源，不推定此前已经隐含。

**语言模式：** [LP09](../engineering/PATTERNS.md#lp09)、[LP22](../engineering/PATTERNS.md#lp22)。

**核心句：** “把当前想法说出来，辨认它是什么。”

**展开：** “请表达你现在对〔对象〕的想法、感受或倾向，再用一个例子说明。核对这是原已有记录支持的内容，还是刚形成的想法；不能确定时保留未知。”

**完成检查：** 主体当前能识别该内容；有前状态材料时再判断是否本次显化。

**边界与失效：** 前状态和来源未知时只确认当前内容，不认定早已隐含；生成新内容不能无证据标成“读出了原本想法”。

**机制候选：** [ME03](../MECHANISMS.md#me03)、[ME04](../MECHANISMS.md#me04)。

<a id="c-p3"></a>

### 认知区分（Differentiation） · C-P3

**状态变化：** 混合认知内容 → 主体能区别内容。

“合作有问题”可能指目标不同、没有明确负责者，也可能指交流让人不适。请主体分别说明：大家要的结果是什么、安排中谁负责、哪段互动产生不适。三个问题的回答可以同时有问题，但所需处理不同，不能只靠把它们分成三列认定本人已会区分。

**操作入口：** [OP06](../engineering/OPERATORS.md#op06)、[OP09](../engineering/OPERATORS.md#op09)。

**怎样做：** 提出容易混同的两项内容；比较区别；让主体说明区别如何改变处理。

**语言模式：** [LP06](../engineering/PATTERNS.md#lp06)、[LP09](../engineering/PATTERNS.md#lp09)。

**核心句：** “区分这两项内容，用区别指导处理。”

**展开：** “请比较〔内容一〕与〔内容二〕，说明它们分别意味着什么。再给出一个需要不同处理的情境，并说明你会怎样据此改变判断或下一步。”

**完成检查：** 能解释区别并据此作不同处理。

**边界与失效：** M1 描述表征结构；M2 检查主体能做出的区分。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="c-p13"></a>

### 边界形成（Boundary Formation） · C-P13

**状态变化：** 对象范围不明 → 有边界对象。

明确主体、范围、时间、条件及排除项。

**相邻区别：** 边界形成划定对象的范围；[具体化](../models/M2.md#c-c1)还按需要澄清对象、条件和关系，使其足够具体。

**操作入口：** [OP10](../engineering/OPERATORS.md#op10)。

**怎样做：** 明确对象、情境、时间与排除项；用范围内外例子检查。

**语言模式：** [LP10](../engineering/PATTERNS.md#lp10)。

**核心句：** “划清对象范围，用范围内外的例子检查。”

**展开：** “请为〔当前对象〕明确情境、时间、纳入项和排除项。再判断〔实例〕属于范围内、范围外还是边界未明，并据此修订必要的边界。”

**完成检查：** 能辨认一个属于范围内、一个属于范围外的例子。

**边界与失效：** 边界为当前工作约定，不等于已证明世界无其他因素。

**机制候选：** [ME01](../MECHANISMS.md#me01)、[ME03](../MECHANISMS.md#me03)。

<a id="c-c1"></a>

### 具体化（Specification） · C-C1

**状态变化：** 模糊对象 → 任务所需的具体对象。

按需要澄清对象、状态、情境、时间、事件或数量，不强制填满。

**操作入口：** [OP09](../engineering/OPERATORS.md#op09)。

**怎样做：** 找影响当前判断的模糊处；补必要对象和条件；用满足与不满足例子检查。

**语言模式：** [LP09](../engineering/PATTERNS.md#lp09)。

**核心句：** “把模糊处具体化到足以判断。”

**展开：** “为〔当前用途〕，找出〔表达〕中会影响判断的模糊处，补明必要对象、条件或事件。请给出满足与不满足描述的例子，检查这些补充是否已足够；未知细节不编造。”

**完成检查：** 他人或主体可以区分至少一个满足和一个不满足描述的情况。

**边界与失效：** 细节增长可能是编造或过早锁定方案。

**可复用组成：** [C-P2](../models/M2.md#c-p2)、[C-P3](../models/M2.md#c-p3)、[C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)。

**机制候选：** [ME01](../MECHANISMS.md#me01)、[ME03](../MECHANISMS.md#me03)。

## 关系（Relation） {#relation}

关系是对象或要素之间的联系，结构是这些要素与关系的组织方式。比较先说明从哪个方面看，也就是比较维度；参照再说明相对于什么。记录口径说明哪些情况计入、怎样记录和计数；口径不同，数字不同未必表示经历本身不同。共同特征与结构对应是两种相似依据，相似本身不证明同因。

<a id="c-p4"></a>

### 比较激活（Comparative Activation） · C-P4

**状态变化：** 单一或分离对象 → 同时进入对照。

使 A 与 B 在同一判断情境下可被比较。

**相邻区别：** 比较激活使对象进入同一对照；[差异识别](../models/M2.md#c-p5)与[相似识别](../models/M2.md#c-p6)分别说明从对照中辨认出了什么。

**操作入口：** [OP06](../engineering/OPERATORS.md#op06)、[OP07](../engineering/OPERATORS.md#op07)。

**怎样做：** 把对象放入同一用途、情境与维度；先确认可比条件，再辨认异同。

**语言模式：** [LP06](../engineering/PATTERNS.md#lp06)、[LP07](../engineering/PATTERNS.md#lp07)。

**核心句：** “把两个对象放进同一个比较情境。”

**展开：** “为〔用途〕，将〔对象一〕与〔对象二〕放在〔共同情境与维度〕下对照。先核对可比条件，明确本次要比较哪个方面，再开始处理异同。”

**完成检查：** 双方对象、情境和比较方面被明确。

**边界与失效：** 激活对照不等于发现差异或形成偏好。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="c-p5"></a>

### 差异识别（Difference Detection） · C-P5

**状态变化：** 差异未明确 → 识别差异。

识别对象在某个方面的不一致。

**操作入口：** [OP06](../engineering/OPERATORS.md#op06)。

**怎样做：** 绑定对象与维度；辨认差异；检查差异是否来自口径或条件变化。

**语言模式：** [LP06](../engineering/PATTERNS.md#lp06)。

**核心句：** “在同一方面找出差异，核对比较口径。”

**展开：** “请比较〔对象一〕与〔对象二〕在〔方面〕上的差异，指出差异内容及材料。再检查差异是否来自记录口径或条件变化；无法比较时说明缺什么。”

**完成检查：** 指出对象、维度和差异内容。

**边界与失效：** 差异不等于缺陷、原因或期望变化。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="c-p6"></a>

### 相似识别（Similarity Detection） · C-P6

**状态变化：** 相似未明确 → 识别相似。

发现共同特征或关系结构。

**操作入口：** [OP07](../engineering/OPERATORS.md#op07)。

**怎样做：** 辨认共同特征或关系；说明相似层面；保留不对应部分。

**语言模式：** [LP07](../engineering/PATTERNS.md#lp07)。

**核心句：** “找出共同点，保留不相似的部分。”

**展开：** “请比较〔对象一〕与〔对象二〕的共同特征或关系，写清相似发生在哪个层面。再指出一个不对应部分及尚未证实的部分，限定这次类比的范围。”

**完成检查：** 能说明同构部分和未证实部分。

这里的“同构部分”按工作用法指已说明的结构对应，不宣称已经证明严格数学同构；表面相似时也须说明相似在哪个方面。

**边界与失效：** 相似不能直接推出相同机制或处理方式。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

<a id="c-p7"></a>

### 参照建立（Reference Establishment） · C-P7

**状态变化：** 参照不明确 → 明确参照。

把“很差”绑定到目标、基线、案例或其他参照。

**相邻区别：** 参照建立说明“相对于什么”；[标准形成](../models/M2.md#c-c8)进一步说明“按什么规则判断”。

**操作入口：** [OP08](../engineering/OPERATORS.md#op08)。

**怎样做：** 明确好坏判断；指出参照来源；检查参照适用性。

**语言模式：** [LP08](../engineering/PATTERNS.md#lp08)。

**核心句：** “为这个评价选定合适的参照。”

**展开：** “你用〔评价词〕判断〔对象〕时，请选出一个可解释的参照，写明来源。核对对象、时间和条件是否适用，再依据这个参照重述评价。”

**完成检查：** 说明参照来源及为何适合当前任务。

**边界与失效：** 参照可能不适用；绑定参照不等于形成完整标准。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME05](../MECHANISMS.md#me05)。

<a id="c-p14"></a>

### 关系形成（Relation Formation） · C-P14

**状态变化：** 孤立要素 → 关系结构。

明确依赖、组成、对照、时序或候选因果关系。

**相邻区别：** 关系形成可以组织组成、依赖、时序或对照；[因果组织](../models/M2.md#c-c3)专门组织候选因果解释及其证据边界。

**操作入口：** [OP34](../engineering/OPERATORS.md#op34)。

**怎样做：** 列要素；逐条指定关系类型；说明依据及未知，必要时用简单关系表。

**语言模式：** [LP34](../engineering/PATTERNS.md#lp34)。

**核心句：** “把要素连接起来，标明关系与依据。”

**展开：** “请列出〔要素〕，逐条写出它们之间的关系类型及依据。组成、依赖、时序与候选因果分别标明；关系未知时保留候选，不由先后出现直接推出因果。”

**完成检查：** 每条关系说明类型与依据。

**边界与失效：** 关系存在的表征不证明该关系真实。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME08](../MECHANISMS.md#me08)。

## 问题（Problem） {#problem}

问题是需要回答、解释或解决的疑问、异常或缺口；候选是尚待检验或选择的可能。这里“假设”主要指判断暂作成立处理的前提（Assumption），例如统计口径未变；候选解释或机制则是待检验的“假说”（Hypothesis），例如记录行为的方式变化造成报表下降。全文出现“机制假设”时按后一用法理解，不默认为已成立前提。

预测是在指定解释与条件下预期会观察到什么；区分性预测要求不同解释给出不同预期。混杂指可能使原因与结果关系被误判的其他因素，例如改版同期用户渠道也改变。列出候选不代表它已发生。详见[认知与解释术语](../GLOSSARY.md#cognition-terms)。

这里回访指用户在指定时间后再次访问；埋点是记录有关行为的程序或事件记录方式，渠道是用户来自哪些入口。以下例子用这些领域材料说明方法，不要求读者先懂产品分析。

例如，报表显示回访减少。候选一是实际回访减少；候选二是记录回访的程序漏记。先指定与哪个先前时期比较，并核对两套记录覆盖同一用户范围、采用同一回访定义和对应的前后时间范围。若独立记录在前后时期可靠，且本轮只比较“实际减少而记录未变”与“实际未减少而报表单纯漏记”两种候选，那么前者预期两套记录都减少，后者预期报表减少而独立记录未减少。这里先说明解释，再说明它在什么条件下预期什么，才提出能区分两者的检查。上述条件或结果未取得时仍是测试提案；两种原因也可能并存，不能把一次对照当作排尽所有原因。

### 问题形成（Problem Formation） · C-C4

**状态变化：** 不满／异常／提问 → 可分析问题。

定位对象、现象、期待、条件和未知；问题不一定来自不满。

**相邻区别：** 问题形成明确待解决或待解释什么；[问题组织](../models/M2.md#c-c5)进一步组织其中的子问题、依赖与冲突。

**操作入口：** [OP35](../engineering/OPERATORS.md#op35)、[OP09](../engineering/OPERATORS.md#op09)、[OP08](../engineering/OPERATORS.md#op08)、[OP10](../engineering/OPERATORS.md#op10)。完整任务可参照[PR04](../engineering/PROTOCOLS.md#pr04)。

**怎样做：** 指认待解决对象；描述现象与期待或提问；确认边界并暂不锁定方案。

**语言模式：** [LP37](../engineering/PATTERNS.md#lp37)、[LP09](../engineering/PATTERNS.md#lp09)、[LP08](../engineering/PATTERNS.md#lp08)、[LP10](../engineering/PATTERNS.md#lp10)。

**核心句：** “把不满或疑问写成一个可分析的问题。”

**展开：** “请说明〔当前情境〕中待解决或待解释的对象，写出观察到的现象及期望、参照或疑问。划定本次范围，形成问题表述；先不要把某个方案当成问题本身。”

**完成检查：** 能说清待解决或待解释什么，而非直接指定方案。

**边界与失效：** 从一个抱怨中推断问题需主体确认。

**可复用组成：** [C-P1](../models/M2.md#c-p1)、[C-P3](../models/M2.md#c-p3)、[C-P7](../models/M2.md#c-p7)、[C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)。

**机制候选：** [ME01](../MECHANISMS.md#me01)、[ME06](../MECHANISMS.md#me06)。

### 问题组织（Problem Structuring） · C-C5

**状态变化：** 混合复杂性 → 有元素、边界与关系的问题结构。

组织子问题、依赖、冲突、优先级和证据缺口。

**操作入口：** [OP09](../engineering/OPERATORS.md#op09)、[OP10](../engineering/OPERATORS.md#op10)、[OP34](../engineering/OPERATORS.md#op34)、[OP19](../engineering/OPERATORS.md#op19)。完整任务可参照[PR04](../engineering/PROTOCOLS.md#pr04)。

**怎样做：** 区分子问题；组织依赖、冲突和优先关系；选择下一项处理或取证。

**语言模式：** [LP09](../engineering/PATTERNS.md#lp09)、[LP10](../engineering/PATTERNS.md#lp10)、[LP34](../engineering/PATTERNS.md#lp34)、[LP19](../engineering/PATTERNS.md#lp19)。

**核心句：** “拆出子问题，组织关系，确定下一步。”

**展开：** “请将〔问题〕分成相关部分，写出它们的依赖、冲突或优先关系及依据。根据已有材料与未知，确定下一项取证或处理；检查这份结构是否能指导它。”

**完成检查：** 结构能指导下一项信息获取或处理。

**边界与失效：** 分类过细但不能指导判断不算完成；无需唯一问题树。

**可复用组成：** [C-P3](../models/M2.md#c-p3)、[C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)、[C-P15](../models/M2.md#c-p15)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME08](../MECHANISMS.md#me08)。

### 候选生成（Alternative Generation） · C-P8

**状态变化：** 候选缺少或单一 → 候选集合扩展。

生成方案、解释、未来状态或行动替代。

**相邻区别：** 候选生成可形成方案、状态或行动替代；[解释生成](../models/M2.md#c-p11)专门为待解释观察提出候选过程。

**操作入口：** [OP11](../engineering/OPERATORS.md#op11)。

**怎样做：** 明确候选用途；生成会改变判断的替代；保留可行性和事实状态。

**语言模式：** [LP11](../engineering/PATTERNS.md#lp11)。

**核心句：** “再生成实质不同的候选。”

**展开：** “为〔候选用途〕，从不同手段、前提或关系生成〔新候选〕，说明它与现有候选有什么会影响判断的差异。合并同义改写，标明可行性与事实状态仍待检查的部分。”

**完成检查：** 候选之间具有会影响判断的实质差异。

**边界与失效：** 数量不等于多样性；候选尚未证实或可行。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME07](../MECHANISMS.md#me07)。

### 搜索限定（Search Bounding） · C-P9

**状态变化：** 搜索范围不明 → 搜索范围明确。

将 Boundary Formation 应用于可进入搜索的对象和条件。

**操作入口：** [OP10](../engineering/OPERATORS.md#op10)。

**怎样做：** 明确搜索目的；划定可进入、暂缓和排除范围；写明重开条件。

**语言模式：** [LP10](../engineering/PATTERNS.md#lp10)。

**核心句：** “限定这次搜索，并写出重开条件。”

**展开：** “为〔搜索目的〕，划出允许进入、暂缓和排除的范围，分别写出理由。再说明出现〔什么新信息或条件变化〕时扩大或改变范围。”

**完成检查：** 明确允许、暂缓或排除的搜索范围及理由。

**边界与失效：** C-P13 的特化；边界可重开，不能伪装成事实排除。

**类型：** [C-P13](../models/M2.md#c-p13) 的领域特化，保留 ID，不计为新独立机制。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

### 假设显化（Assumption Explication） · C-P10

**状态变化：** 未明示前提 → 明示前提。

将 Explication 应用于判断所依赖的假设。

**相邻区别：** 假设显化将前提写明；[假设审查](../models/M2.md#c-c2)再检查该前提的材料、反例与适用范围。

**操作入口：** [OP12](../engineering/OPERATORS.md#op12)。

**怎样做：** 写出判断所依赖的前提；说明前提失效会影响哪一步；标来源状态。

**语言模式：** [LP12](../engineering/PATTERNS.md#lp12)。

**核心句：** “把判断依赖的前提写出来。”

**展开：** “请定位〔判断〕的推理，写出它依赖的条件，并确认哪些原已默认、哪些刚提出。逐项说明：如果这个条件不成立，哪一步需要重审？标明来源与未知。”

**完成检查：** 能写出如果假设不成立，哪条判断需重审。

**边界与失效：** C-P2 的特化；不要把事后合理化当已有前提。

**类型：** [C-P2](../models/M2.md#c-p2) 的领域特化，保留 ID，不计为新独立机制。

**机制候选：** [ME04](../MECHANISMS.md#me04)。

### 解释生成（Explanation Generation） · C-P11

**状态变化：** 待解释观察 → 候选解释。

提出能连接观察与可能条件或过程的解释。

**操作入口：** [OP11](../engineering/OPERATORS.md#op11)。

**怎样做：** 描述待解释观察；提出连接观察的候选过程；给出可区分的预测。

**语言模式：** [LP11](../engineering/PATTERNS.md#lp11)。

**核心句：** “为这个现象提出可检查的解释。”

**展开：** “针对〔观察〕，提出一个能连接相关事件的候选过程，说明它怎样产生该现象。请写出若解释成立预期看到什么、从哪里查；解释与已知观察分别记录。”

**完成检查：** 说明解释对象、候选过程和可区分预测。

**边界与失效：** 流畅解释不是证据，时间先后不足以证明因果。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

### 解释多样化（Explanation Diversification） · C-P12

**状态变化：** 解释单一 → 多个竞争解释。

将 Alternative Generation 应用于解释空间。

**操作入口：** [OP11](../engineering/OPERATORS.md#op11)。

**怎样做：** 围绕同一观察生成竞争解释；要求解释给出不同预测；避免同义改写。

**语言模式：** [LP11](../engineering/PATTERNS.md#lp11)。

**核心句：** “再提一种能产生不同预测的解释。”

**展开：** “针对同一〔观察〕，从不同条件或过程提出〔竞争解释〕。请分别写出不同预测，并指出什么材料可以区分；换一种措辞但预测相同的不算实质不同。”

**完成检查：** 至少提出一个能给出不同预测的替代。

**边界与失效：** C-P8 的特化；没有差异预测的改名不算新解释。

**类型：** [C-P8](../models/M2.md#c-p8) 的领域特化，保留 ID，不计为新独立机制。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

### 假设审查（Assumption Examination） · C-C2

**状态变化：** 已明示假设 → 已检查假设。

检查证据、反例、边界和替代，并可保留或撤回。

**操作入口：** [OP12](../engineering/OPERATORS.md#op12)、[OP13](../engineering/OPERATORS.md#op13)、[OP14](../engineering/OPERATORS.md#op14)。完整任务可参照[PR06](../engineering/PROTOCOLS.md#pr06)。

**怎样做：** 明确前提；查材料、反例与边界；决定保持、修改或保留未知。

**语言模式：** [LP12](../engineering/PATTERNS.md#lp12)、[LP13](../engineering/PATTERNS.md#lp13)、[LP14](../engineering/PATTERNS.md#lp14)。

**核心句：** “用材料和反例检查这个前提。”

**展开：** “请明确〔前提〕及范围，查支持、冲突和未知，再提出并核验针对它的反例。依据这些材料决定保持、修改或暂不判断，并说明结论需要怎样调整。”

**完成检查：** 记录支持、冲突、未知及条件，不以反对数量代替检验。

**边界与失效：** 没有反例不等于证实；并非每个假设都可立即实验。

**可复用组成：** [C-P10](../models/M2.md#c-p10)、[C-P19](../models/M2.md#c-p19)、[C-P8](../models/M2.md#c-p8)、[C-P13](../models/M2.md#c-p13)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME04](../MECHANISMS.md#me04)、[ME08](../MECHANISMS.md#me08)。

### 因果组织（Causal Structuring） · C-C3

**状态变化：** 观察／序列 → 候选因果结构。

组织实体、时间、机制假设、竞争解释与可区分预测。

**操作入口：** [OP11](../engineering/OPERATORS.md#op11)、[OP34](../engineering/OPERATORS.md#op34)、[OP13](../engineering/OPERATORS.md#op13)。完整任务可参照[PR04](../engineering/PROTOCOLS.md#pr04)。

**怎样做：** 组织观察、时序与候选过程；比较竞争预测；标证据、混杂及未知。

**语言模式：** [LP11](../engineering/PATTERNS.md#lp11)、[LP34](../engineering/PATTERNS.md#lp34)、[LP13](../engineering/PATTERNS.md#lp13)。

**核心句：** “组织候选因果关系，标明证据与混杂。”

**展开：** “请把〔材料〕中的观察、先后顺序和候选因果过程分开，写出关系结构。逐条标明证据与未知，指出可能同时影响两者的条件；比较竞争解释的预测，不把箭头当成已证实因果。”

**完成检查：** 说明哪些箭头有证据，哪些只是候选，指出混杂可能。

**边界与失效：** 可解释不等于识别因果；想象干预不能替代真实研究。

**可复用组成：** [C-P3](../models/M2.md#c-p3)、[C-P11](../models/M2.md#c-p11)、[C-P12](../models/M2.md#c-p12)、[C-P14](../models/M2.md#c-p14)、[C-P19](../models/M2.md#c-p19)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME08](../MECHANISMS.md#me08)。

## 目标（Goal） {#goal}

偏好是当前更趋近或回避什么的倾向；期望状态是希望出现什么情况；目标是主体已经采纳、准备投入资源追求的对象或状态。采纳说明是否准备追求，手段说明怎样实现。比如“更自主”可展开为自己决定工作时段、减少等待批准等期望方面，但这些不自动成为已采纳目标。

<a id="c-p17"></a>

### 偏好形成（Preference Formation） · C-P17

**状态变化：** 候选状态／方向 → 情境中的倾向。

激活、显化或构造趋近／回避偏好；记录哪一种仍未知。

**相邻区别：** 偏好形成说明当前更倾向什么；[选项选择](../models/M2.md#c-p21)说明实际确定了哪个选项，选择可以受其他条件影响。

**操作入口：** [OP15](../engineering/OPERATORS.md#op15)。

**怎样做：** 呈现候选方向和条件；由主体说明趋近或回避倾向；允许未知。

**语言模式：** [LP15](../engineering/PATTERNS.md#lp15)。

**核心句：** “比较这些方向，表达当前的倾向。”

**展开：** “在〔当前条件〕下，请比较〔候选方向〕，说明你愿意趋近、回避或尚无法比较什么及理由。检查是否有选项未覆盖；暂时没有倾向也可以明确记录。”

**完成检查：** 主体能指出当前倾向、条件与不确定性；无法形成偏好时记录目标未达成或未知，允许暂停。

**边界与失效：** 差异检测不是必要条件；不声称直接读出稳定真实偏好。

**机制候选：** [ME05](../MECHANISMS.md#me05)。

<a id="c-p16"></a>

### 期望状态构造（Desired-State Construction） · C-P16

**状态变化：** 偏好方向 → 可表征期望状态。

将“更自主”写成有关对象的期望状态，例如自己决定工作时段、减少等待批准；可以先说明关系或方向，不强制量化。这里的特征仍指描述状态的方面，不是一个叫“偏好特征”的新概念。

**相邻区别：** 期望状态构造说明希望出现什么状态；[目标采纳](../models/M2.md#c-p18)说明主体是否准备投入资源追求该状态。

**操作入口：** [OP16](../engineering/OPERATORS.md#op16)。

**怎样做：** 描述希望变得不同的对象与特征；保留约束状态；区分期望和实现手段。

**语言模式：** [LP16](../engineering/PATTERNS.md#lp16)。

**核心句：** “把希望的方向写成变化后的状态。”

**展开：** “从〔偏好方向〕出发，请描述〔对象〕变化后的有关特征，以及在具体情境中会有什么不同。把期望状态与实现手段分开，保留约束和仍不确定的部分。”

**完成检查：** 能描述如果变化发生会有什么不同。

**边界与失效：** 不强制真实可行，但后续重新纳入约束；状态不自动绑定方案。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME07](../MECHANISMS.md#me07)。

<a id="c-c6"></a>

### 期望变化形成（Desired-Change Formation） · C-C6

**状态变化：** 当前状态／不满／模糊方向 → 期望变化表征。

已有参照时，可说明希望接近它的哪一方面；没有明确方向时，可先生成不同状态供主体评价；只知道不愿继续承受什么时，可从该回避对象寻找替代。三者是按现有输入选择的做法，不是需要另学的三条理论路线。

**操作入口：** [OP16](../engineering/OPERATORS.md#op16)、[OP15](../engineering/OPERATORS.md#op15)、[OP06](../engineering/OPERATORS.md#op06)、[OP11](../engineering/OPERATORS.md#op11)。完整任务可参照[PR02](../engineering/PROTOCOLS.md#pr02)。

**怎样做：** 按现有输入澄清当前与期望；需要时比较或生成替代；由主体确认变化方向。

**语言模式：** [LP16](../engineering/PATTERNS.md#lp16)、[LP15](../engineering/PATTERNS.md#lp15)、[LP06](../engineering/PATTERNS.md#lp06)、[LP11](../engineering/PATTERNS.md#lp11)。

**核心句：** “说明希望哪一方面从现在变成怎样。”

**展开：** “请根据已有材料描述〔当前状态〕，由你说明希望〔哪方面〕变成〔何种状态或方向〕。不清楚时先比较现状与可能状态，或从不愿继续承受的情况生成替代，再由你确认方向。”

**完成检查：** 说清哪方面从何种状态向何种状态变化，允许暂时只明确方向。

**边界与失效：** 不固定必经差异检测；输入当前状态未知时先查，而不编造。

**可复用组成：** [C-P4](../models/M2.md#c-p4)、[C-P5](../models/M2.md#c-p5)、[C-P8](../models/M2.md#c-p8)、[C-P17](../models/M2.md#c-p17)、[C-P16](../models/M2.md#c-p16)、[C-P14](../models/M2.md#c-p14)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME05](../MECHANISMS.md#me05)、[ME07](../MECHANISMS.md#me07)。

<a id="c-p18"></a>

### 目标采纳（Goal Adoption） · C-P18

**状态变化：** 期望状态 → 主体采纳的目标。

主体把某状态作为准备投入资源追求的对象。

**相邻区别：** 目标采纳是主体愿意追求的核心变化；[目标形成](../models/M2.md#c-c7)围绕采纳按需要补边界、优先关系或标准。

**操作入口：** [OP17](../engineering/OPERATORS.md#op17)。

**怎样做：** 由主体确认是否准备投入资源追求；区分觉得不错与采纳；记录范围。

**语言模式：** [LP17](../engineering/PATTERNS.md#lp17)。

**核心句：** “确认是否愿意投入去追求这个期望。”

**展开：** “对于〔期望状态〕，请你决定采纳、暂缓还是不采纳，并说明愿意投入的范围及有关条件。把觉得不错、继续探索与准备追求分别记录，不替你作采纳决定。”

**完成检查：** 确认主体愿意追求，而非只认为它不错。

**边界与失效：** 内部采纳不等于社会承诺；不要求先有精确指标或时限。

**机制候选：** [ME09](../MECHANISMS.md#me09)。

<a id="c-c7"></a>

### 目标形成（Goal Formation） · C-C7

**状态变化：** 期望变化 → 已采纳且可继续规格化的目标。

保留目标采纳的核心，按需要澄清对象、边界、优先级与标准。

**操作入口：** [OP17](../engineering/OPERATORS.md#op17)、[OP16](../engineering/OPERATORS.md#op16)、[OP10](../engineering/OPERATORS.md#op10)、[OP18](../engineering/OPERATORS.md#op18)。完整任务可参照[PR02](../engineering/PROTOCOLS.md#pr02)。

**怎样做：** 确认采纳；只补影响后续处理的边界、优先级或标准；保留未采纳想法。

**语言模式：** [LP17](../engineering/PATTERNS.md#lp17)、[LP16](../engineering/PATTERNS.md#lp16)、[LP10](../engineering/PATTERNS.md#lp10)、[LP18](../engineering/PATTERNS.md#lp18)。

**核心句：** “采纳要追求的目标，补明必要边界。”

**展开：** “请先确认你是否准备追求〔期望变化〕；采纳后，只补明影响后续处理的范围、优先关系或判断要求。把未采纳的想法另记，检查你能否据此继续规划。”

**完成检查：** 主体确认实际采纳，并能区分其与未采纳期望及继续规格化需求；未采纳时不登记此目标已达成。

**边界与失效：** 标准、时间、数量不是目标存在的通用必要条件。

**可复用组成：** [C-P18](../models/M2.md#c-p18)、[C-P13](../models/M2.md#c-p13)、[C-P15](../models/M2.md#c-p15)、[C-C8](../models/M2.md#c-c8)。

**机制候选：** [ME09](../MECHANISMS.md#me09)。

## 决策（Decision） {#decision}

维度说明从哪个方面评价；标准说明按什么规则判断；指标提供可观察线索；度量说明怎样计数或测量；阈值说明在哪里触发或达到某项判定。例如准确性是维度，数字与原材料一致是规则，错误次数是指标，怎样计一次错误是度量，容许错误数是阈值。按需使用即可。硬条件不能靠其他优点抵消，部分排序允许有些选项暂不可比较。

为什么从“准确”走到这条规则？假设本次报告用于核对已给定的数据，数字写错会妨碍这个用途，因此可提出“关键数字、单位与时间须和指定材料一致”的规则。它的适用依据是该报告用途；若报告用于讨论尚未发生的预测，还需要区分估计与事实，不能原样套用。给定规则后，才按规则找材料并判断具体报告。标准的提出与标准是否适合当前用途，也分别检查。

<a id="c-c8"></a>

### 标准形成（Criteria Formation） · C-C8

**状态变化：** 标准缺失／隐含／不足 → 可用于判断的标准。

明确评价对象、用途与规则；指标、阈值、证据按需要绑定。

**相邻区别：** 标准形成建立个人可用于判断的规则；[验收标准形成](../models/M4.md#a-p16)将规则纳入主体间任务的验收安排。

**操作入口：** [OP18](../engineering/OPERATORS.md#op18)。完整任务可参照[PR03](../engineering/PROTOCOLS.md#pr03)。

**怎样做：** 确定评价用途；形成可判断的规则；用满足、不满足与缺材料例子检查。

**语言模式：** [LP18](../engineering/PATTERNS.md#lp18)。

**核心句：** “写出判断规则，用具体实例试判。”

**展开：** “为〔评价对象与用途〕，从目标、约束或既有要求写出判断规则，说明所需材料。请用满足、不满足和材料不足的实例试判；不能支持判断时修订规则。”

**完成检查：** 已有规则能支持具体判断，包括按该规则因材料不足判为未知；只有“缺材料”而无判断规则时，不登记标准已形成。

**边界与失效：** 目标是输入之一；不强制量化、加权总分或唯一排名。

**可复用组成：** [C-P2](../models/M2.md#c-p2)、[C-P3](../models/M2.md#c-p3)、[C-P8](../models/M2.md#c-p8)、[C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)、[C-P15](../models/M2.md#c-p15)。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME09](../MECHANISMS.md#me09)。

<a id="c-p15"></a>

### 优先排序（Prioritization） · C-P15

**状态变化：** 未排序要素 → 有优先关系。

形成重要性、紧迫性、依赖先后或硬条件结构。

**相邻区别：** 优先排序给出重要性或先后关系；[选项选择](../models/M2.md#c-p21)指定当前选择，二者不必同时发生。

**操作入口：** [OP19](../engineering/OPERATORS.md#op19)。

**怎样做：** 确定排序用途与规则；形成必要的先后关系；保留不可比较项。

**语言模式：** [LP19](../engineering/PATTERNS.md#lp19)。

**核心句：** “按用途排出必要的先后关系。”

**展开：** “为〔排序用途〕，明确排序依据，比较〔事项〕并写出先后关系及理由。允许并列或不可比较；只排列会影响当前处理的关系。”

**完成检查：** 说明按什么排序，并保留不可比较项。

**边界与失效：** 优先级不是最终决定；不可比较不硬造总排名。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME09](../MECHANISMS.md#me09)。

<a id="c-c9"></a>

### 候选评价（Alternative Evaluation） · C-C9

**状态变化：** 候选集合 → 带依据与未知的候选评价。

根据标准检查条件、后果、证据和冲突；输出可为部分排序。

**相邻区别：** 候选评价给出带依据、代价与未知的评价；[决策形成](../models/M2.md#c-c10)在当前条件下形成选择及停止理由。

**操作入口：** [OP19](../engineering/OPERATORS.md#op19)、[OP13](../engineering/OPERATORS.md#op13)、[OP18](../engineering/OPERATORS.md#op18)。完整任务可参照[PR05](../engineering/PROTOCOLS.md#pr05)。

**怎样做：** 复用或补判断规则；逐候选核对材料、代价与未知；保留部分排序。

**语言模式：** [LP19](../engineering/PATTERNS.md#lp19)、[LP13](../engineering/PATTERNS.md#lp13)、[LP18](../engineering/PATTERNS.md#lp18)。

**核心句：** “按规则逐项评价，保留代价与未知。”

**展开：** “请复用或补足〔评价规则〕，逐一核对〔候选〕的材料、后果、代价与冲突。写出每项评价的规则和依据，保留未知、不可比较及只能排部分先后的情况。”

**完成检查：** 对每项评价能追溯规则和材料；保留未知／不可比较。

**边界与失效：** 更偏好不等于证据支持，缺失值不能填零；评价不要求已选。

**可复用组成：** [C-C8](../models/M2.md#c-c8)、[C-P7](../models/M2.md#c-p7)、[C-P19](../models/M2.md#c-p19)、[C-P14](../models/M2.md#c-p14)、[C-P15](../models/M2.md#c-p15)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME08](../MECHANISMS.md#me08)。

<a id="c-p21"></a>

### 选项选择（Option Selection） · C-P21

**状态变化：** 选择未确定 → 选择已确定。

在当前规则下指定要采取、试验、暂缓或放弃的选项。

例如，某候选需要一项尚未确认的授权，而当前规则禁止未授权执行；在查清前选择暂缓。这是“规则＋材料状态”支持的当前选择，既不证明该候选永远不可行，也不证明其他候选更好。继续搜索何时停止，同样须交代当前任务的依据，不能仅以“已经想够了”说明最优。

**操作入口：** [OP20](../engineering/OPERATORS.md#op20)。

**怎样做：** 在已有条件与规则下指定当前选择；允许试验、暂缓或退出；给出重开条件。

**语言模式：** [LP20](../engineering/PATTERNS.md#lp20)。

**核心句：** “明确本轮选择，并说明何时重选。”

**展开：** “依据〔当前材料与规则〕，请确定〔本轮选择〕及适用条件；可以选择行动、试验、暂缓或退出。写出〔何种新情况〕出现时需要重开选择。”

**完成检查：** 说明所选对象、适用条件与改变选择的触发。

**边界与失效：** 选择不是行动；本接口不声称实现最优或解释全部决策机制。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME09](../MECHANISMS.md#me09)。

<a id="c-c10"></a>

### 决策形成（Decision Formation） · C-C10

**状态变化：** 待选情境／候选评价 → 选择及其理由。

明确选择问题、最低要求、比较规则、未知容忍和搜索停止条件，再选择。

**操作入口：** [OP20](../engineering/OPERATORS.md#op20)、[OP19](../engineering/OPERATORS.md#op19)、[OP10](../engineering/OPERATORS.md#op10)。完整任务可参照[PR05](../engineering/PROTOCOLS.md#pr05)。

**怎样做：** 确定决策对象与限制；处理必要评价和未知；明确选择及停止、重开条件。

**语言模式：** [LP20](../engineering/PATTERNS.md#lp20)、[LP19](../engineering/PATTERNS.md#lp19)、[LP10](../engineering/PATTERNS.md#lp10)。

**核心句：** “处理必要的评价，作出有理由的决定。”

**展开：** “为〔决策问题〕，先确定限制，处理会影响选择的评价和未知，再明确行动、可逆试验、暂缓或退出。请写出理由、停止搜索的依据及重开条件。”

**完成检查：** 可记录行动选择、可逆试验、暂缓或退出，以及重开条件。

**边界与失效：** 多个方案不必先完整评分；决策不保证最优，也不等于执行。

**可复用组成：** [C-C9](../models/M2.md#c-c9)、[C-P13](../models/M2.md#c-p13)、[C-P15](../models/M2.md#c-p15)、[C-P20](../models/M2.md#c-p20)、[C-P21](../models/M2.md#c-p21)。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME09](../MECHANISMS.md#me09)。

## 计划（Plan） {#plan}

计划组织实现目标的手段、步骤、资源与依赖；依赖说明下一步需要什么输入或条件。实施意图进一步把可辨认的情境线索与具体行为绑定，例如“开始阅读时先关闭提醒”；形成这种绑定与以后实际执行分别检查。

例如，为判断暂停提醒是否值得继续，需要一次有记录的尝试。由此才提出：先确定可暂停哪些提醒，再记录阅读、中断和恢复情况，最后按原先目的检查材料。“需要记录”连接了目标与步骤；若记录方式、操作权限或开始条件未知，计划还留有缺口。把步骤列出来没有证明尝试会成功，形成线索—动作绑定也没有证明以后会照做。

<a id="c-c13"></a>

### 计划形成（Plan Formation） · C-C13

**状态变化：** 已采纳目标／选择 → 实现路径与依赖计划。

生成手段，检查资源与约束，组织步骤、依赖、检查点和回退。

**相邻区别：** 计划形成组织实现路径；[实施意图形成](../models/M2.md#c-c14)进一步把可辨认的情境线索与具体动作及例外绑定。

**操作入口：** [OP21](../engineering/OPERATORS.md#op21)、[OP11](../engineering/OPERATORS.md#op11)、[OP19](../engineering/OPERATORS.md#op19)。完整任务可参照[PR10](../engineering/PROTOCOLS.md#pr10)。

**怎样做：** 围绕已采纳目标组织手段、资源与依赖；确定可开始的下一步及回退。

**语言模式：** [LP21](../engineering/PATTERNS.md#lp21)、[LP11](../engineering/PATTERNS.md#lp11)、[LP19](../engineering/PATTERNS.md#lp19)。

**核心句：** “从目标组织路径，落实可开始的下一步。”

**展开：** “围绕〔已采纳目标或选择〕，组织实现所需产物、手段、资源与依赖。请明确可开始的下一步、检查点及阻塞时的回退或替代；缺少的条件另记。”

**完成检查：** 下一步可执行且与目标有关；关键依赖、未知和备选已明确。

**边界与失效：** 内部计划属于 M2；任务分配和对外义务进入 M4。

**可复用组成：** [C-P8](../models/M2.md#c-p8)、[C-C9](../models/M2.md#c-c9)、[C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)、[C-P15](../models/M2.md#c-p15)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME07](../MECHANISMS.md#me07)、[ME09](../MECHANISMS.md#me09)。

<a id="c-c14"></a>

### 实施意图形成（Implementation-Intention Formation） · C-C14

**状态变化：** 目标／计划 → 情境线索—行动绑定。

主体把可识别触发条件与具体行动及例外联系起来。

**操作入口：** [OP32](../engineering/OPERATORS.md#op32)。完整任务可参照[PR10](../engineering/PROTOCOLS.md#pr10)。

**怎样做：** 识别可辨认线索；绑定可行动作和例外；由主体采纳，执行另查。

**语言模式：** [LP32](../engineering/PATTERNS.md#lp32)。

**核心句：** “如果出现这个线索，我就执行这个动作。”

**展开：** “为〔已采纳目标〕，我采纳这样的安排：如果出现〔可识别线索〕，我就执行〔具体可行动作〕。请说明如何识别线索、第一步是什么，以及例外、冲突或重复触发怎样处理。”

**完成检查：** 主体采纳线索—行动绑定，能识别触发、说明具体动作与不应执行的例外；实际执行另查。

**边界与失效：** 动作可行性须按任务另查；形成绑定不证明以后会执行。可保持纯 M2，不因行动词归入 M4，条件句也不是效果证明。

**可复用组成：** [C-P13](../models/M2.md#c-p13)、[C-P14](../models/M2.md#c-p14)、[C-C1](../models/M2.md#c-c1)、[C-P18](../models/M2.md#c-p18)。

**机制候选：** [ME09](../MECHANISMS.md#me09)。

## 反思（Reflection） {#reflection}

主张是提出的具体说法，证据是对该说法有支持或限制作用的材料及依据，信念是当前持有的判断，信心是对其可靠程度的估计。元认知关注自己怎样判断及局限；反思可以保持原结论。C-C11保留“信念校准”名称，工作含义是按证据调整或保持判断；统计校准另需一组预测与实际结果，不能由单次文字审查完成。

<a id="c-p19"></a>

### 证据关联（Evidence Linking） · C-P19

**状态变化：** 判断与材料未关联 → 主张—材料关联。

将 Relation Formation 特化为来源、支持／反驳关系与适用范围。

**操作入口：** [OP13](../engineering/OPERATORS.md#op13)。

**怎样做：** 定位主张；定位材料；逐项说明支持、冲突与不支持的部分。

**语言模式：** [LP13](../engineering/PATTERNS.md#lp13)。

**核心句：** “把每项主张接到相应材料。”

**展开：** “请定位〔主张〕及可查〔材料〕，逐项写出支持、冲突、无关或未知的关系。核对来源、时间与范围，说明材料支持到哪一步、哪些结论仍不能推出。”

**完成检查：** 写清材料支持哪一步，哪些部分仍未知。

**边界与失效：** C-P14 的特化；引用存在不等于支持，关联不等于校准。

**类型：** [C-P14](../models/M2.md#c-p14) 的领域特化，保留 ID，不计为新独立机制。

**机制候选：** [ME04](../MECHANISMS.md#me04)、[ME08](../MECHANISMS.md#me08)。

<a id="c-p20"></a>

### 不确定性表征（Uncertainty Representation） · C-P20

**状态变化：** 未知程度未区分 → 明确未知与置信范围。

将已知、推测、信息不足或概率判断分开。

本卡所说“置信范围”用于说明对判断有多大把握、哪些部分仍不能确定，允许先用有依据的定性描述；不统一要求统计置信区间。若另给概率或统计区间，需要相应方法与数据；不能靠填写一个精确数字消除未知。

**操作入口：** [OP13](../engineering/OPERATORS.md#op13)。

**怎样做：** 把已知、推测和缺材料处标开；说明判断依据及更新条件。没有结果材料时，采用OP13的未知定位变体，只说明缺什么以及怎样查，不补写证据已经关联。

**语言模式：** [LP13](../engineering/PATTERNS.md#lp13)。

**核心句：** “把已知、推测与未知分开写。”

**展开：** “关于〔问题〕，请分别标出已有依据、推测和缺材料的部分，并说明当前判断范围。为未知写出取得什么材料、怎样查以及怎样更新；没有证据时不补造支持关系。”

**完成检查：** 说明何处未知、依据什么及怎样可能更新。

**边界与失效：** 精确数字不代表统计校准；低自信也不等于正确。

**机制候选：** [ME04](../MECHANISMS.md#me04)。

<a id="c-c12"></a>

### 元认知表征（Metacognitive Representation） · C-C12

**状态变化：** 认知活动 → 对活动及其局限的表征。

观察自己依据什么、忽略什么、怎样形成判断，并检查行为迹象。

**操作入口：** [OP22](../engineering/OPERATORS.md#op22)。完整任务可参照[PR06](../engineering/PROTOCOLS.md#pr06)。

**怎样做：** 描述自己的判断过程；区分实际记录与事后解释；检查遗漏和局限。

**语言模式：** [LP22](../engineering/PATTERNS.md#lp22)。

**核心句：** “回看自己的判断过程，标出局限。”

**展开：** “请说明你怎样得出〔判断〕，对照当时的材料、选择或行为记录。区分有记录的步骤与事后解释，指出遗漏和未知；对象判断与对过程的描述分开。”

**完成检查：** 能区分对对象的判断与对判断过程的描述。

**边界与失效：** 自述机制可能事后合理化；AI 的自解释不能直接证明内部推理。

**可复用组成：** [C-P1](../models/M2.md#c-p1)、[C-P2](../models/M2.md#c-p2)、[C-P10](../models/M2.md#c-p10)、[C-P19](../models/M2.md#c-p19)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME04](../MECHANISMS.md#me04)。

<a id="c-c11"></a>

### 信念校准（Belief Calibration） · C-C11

**状态变化：** 证据、范围与信心未匹配 → 依据证据调整的信念。

审查主张、材料、反例、范围与未知，保持或调整判断。

**相邻区别：** 信念校准根据材料调整或保持判断；[元认知表征](../models/M2.md#c-c12)描述判断怎样形成及其局限，反思过程不必导致结论变化。

**操作入口：** [OP22](../engineering/OPERATORS.md#op22)、[OP13](../engineering/OPERATORS.md#op13)、[OP12](../engineering/OPERATORS.md#op12)、[OP14](../engineering/OPERATORS.md#op14)。完整任务可参照[PR06](../engineering/PROTOCOLS.md#pr06)。

**怎样做：** 核对主张、前提和证据；说明新材料是否改变推理；保持或修订范围与信心。用OP22时选择判断修订变体，不能仅凭对过程的自述登记此接口达成。

**语言模式：** [LP22](../engineering/PATTERNS.md#lp22)、[LP13](../engineering/PATTERNS.md#lp13)、[LP12](../engineering/PATTERNS.md#lp12)、[LP14](../engineering/PATTERNS.md#lp14)。

**核心句：** “用新材料校准判断的范围与信心。”

**展开：** “请把〔新材料〕与〔原主张、前提和依据〕对应，检查它改变了哪一步以及支持到什么范围。说明据此保持或修订结论与信心的理由；没有改变时可以保留原判断。”

**完成检查：** 修改需指出新信息与原推理变化；未知可被保留。

**边界与失效：** ID 旧名保留；单次文字审查不是统计校准，后者需结果序列。

**可复用组成：** [C-P19](../models/M2.md#c-p19)、[C-C2](../models/M2.md#c-c2)、[C-P13](../models/M2.md#c-p13)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME04](../MECHANISMS.md#me04)、[ME08](../MECHANISMS.md#me08)。
