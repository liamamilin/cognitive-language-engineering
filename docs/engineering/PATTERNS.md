# Pattern Library｜语言模式与语境

Pattern是可改写的语言形式及适用条件；实例化是把其中的待填位置（槽位）换成当前真实对象和条件。实际语言实例（utterance）还绑定主体、媒介、前文、状态和关系。Pattern 与 Operator / Protocol 是多对多，句子形式不能唯一决定功能。

例如，“具体指什么？”在本人尚不清楚对象时可以帮助具体化，在双方用词不同的时候可以用于澄清。方法由当前缺口、实际处理和检查决定；同一个句式提供表达入口，不独自决定其算子归属或结果。

为避免两套手工编辑的正文，LP01—LP34及LP37—LP39 的主句与变体直接维护在算子卡片；本页提供用途映射与组合模式。

[学习连接索引](../learning/INTERFACE_PATHS.md)可从接口找到方法与模式；以下模式号是稳定ID，新算子的主模式号不必与算子号相同。LP35/LP36沿用原组合模式。

模型卡片中的“语言模式示例”展示某个接口下的可复用写法；〔……〕标示待填位置。比如“这里的〔概念〕指什么？给出一个正例、一个反例和一个边界例”，展示概念形成的表达形式；填入“外部中断”后，得到一个具体情境例句。例句帮助理解怎样改写，不把这一主题限制为模式的唯一用途。实际语言实例还需主体和语境，不能从句式独自判定操作或结果。

<a id="lp35"></a>
## LP35. Desired-Change Micro-Protocol｜“你希望什么变得不同？”

微协议（Micro-Protocol）是在短小表达或少量轮次中组合多个有条件操作的方式。此模式可以简短承载期望变化的微协议；问句短不表示只发生一种操作。可能调用 OP09 当前状态具体化、OP06 对照、OP11 替代生成、OP15 偏好与 OP16 期望状态构造；不是只执行 Difference。

若主体已有期望状态，只需澄清或确认，不再重走全部链。若只能说不想要什么，先明确回避对象，再生成替代；若不知道当前状态，先获取材料。单次回答也可能只完成其中一部分。

<a id="lp36"></a>
## LP36. Completion Clarification｜“你说的完成，具体意味着什么？”

可能执行 OP09 具体化、OP18 标准形成、OP24 含义对齐，或 OP28 将标准绑定到任务。只看到问句不能确定归属；检查变化发生于内部判断、主体间理解还是任务约定。

## 调整原则

1. 不在问题中预填未经确认的目标或立场。
2. 允许“不知道”“不同意”“无法比较”和“需要查证”。
3. 区分请求理解、请求评价和请求采纳，不用同一句“你明白吧”代替。
4. 对术语歧义使用例子和反例；对事实未知获取材料，不能靠不断换问法制造答案。
5. 对 AI 使用可检查的文本和行为条件；对人保留主体确认与意义协商。

## 同一句话的三种使用

“你说的完成，具体意味着什么？”可以是本人澄清目标、双方核对术语，也可以是形成验收约定。选哪种解释，要看主体、前状态、任务和实际输出。

| 当前缺口 | 可能操作 | 必须检查 |
| --- | --- | --- |
| 本人不知道怎样判断 | OP18 | 是否得到规则，不仅是形容词 |
| 两人使用不同含义 | OP24 | 是否在指定范围形成共同解释 |
| 已有规则但未进入任务安排 | OP28 | 谁按什么依据采用哪个版本的验收规则 |

如果规则已经有效，只缺结果材料，这句话未必适用；应按规则取得材料。语言模式的多对多关系通过这种语境差异体现，而非给每个句子增加更多标签。

实例化前只检查影响本次用途的槽位：谁、哪个对象、哪项范围、什么材料、请求哪种响应。信息不明时澄清或保留未知，不为模板完整而编造。句子的礼貌、长度或肯定程度不能代替目标达成检查。

<a id="lp37"></a>
## LP37. Focus / Feature Selection｜聚焦与特征选择

特征是对象或经验可辨认和描述的方面，如账号状态、错误类型；具体取值和信息来源另记。主句与语境变体维护在[OP35](OPERATORS.md#op35)。模式：“为了当前用途，先看什么？哪些特征会改变判断，哪些暂时略去？”

该形式用于尝试相应操作；是否产生接口所需结果，须按算子和接口检查，不凭句式判定。
