# Operator Library｜可调用操作

版本 v0.5。所有卡片为正式工程规格；组件效果默认 E0。具体调用是否有帮助，需要任务、状态、语言实例和评价材料，不能继承相关机制的证据等级。

## 统一接口

各卡片的“完成检查”只检查目标，不默认所有目标变化都发生。统一按[使用规格](RUN_SPEC.md)分开执行、产物、目标与结束；前状态未知时不登记本次提升，多个目标允许部分达成。

每张卡片包含名称、任务、前提、目标变化、输出、过程／机制候选、主模式、变体与语境、检查方式、失效、扭曲／取舍、易混对象、应用情境和证据状态。相关 Transition 定义记录目标变化；此处提供促成变化的操作。

使用顺序：判断当前缺口 → 选卡 → 调整句子 → 检查实际输出 → 必要时换卡或停止。下列语言仅是模式例子，不能直接视为完整协议。

## OP01. Removal

**任务／应用情境：** 探索候选依赖或必要条件；适用于具有下列前提的自我思考、互动或技术协作情境。

**前提：** 能辨认 X 及相关结果 Y。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-C3](../models/M2.md#c-c3)。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

**语言模式 LP01：** “如果 X 不存在，哪些结果可能仍出现？”

**变体与使用条件：** “在保持哪些条件不变时再讨论？” 使用时绑定对象、主体、语境与当前状态；不要重复已经明确的内容。

**操作与输出：** 先明确结果 Y、待移除对象 X 及暂时保持的条件；生成无 X 的候选路径；指出哪些依赖会随移除一起改变，再提出现实核验需求。 输出：带条件的反事实候选与验证需求。

**完成检查：** 标记想象与观察，指出可检验差异。

**主要失效：** 反事实模型不清却得出必要性结论。

**取舍与扭曲：** 简化情境可能遗漏关联条件。

**易混对象：** 真实消融／干预实验。

**证据／评价：** CLE 规格与映射 E0；用完成检查、前后材料及失效案例评估，不以回答长度或同意程度代替结果。

## OP02. Replacement

**任务／应用情境：** 打开实现手段空间；适用于具有下列前提的自我思考、互动或技术协作情境。

**前提：** 原目的与当前手段能被区别。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-P3](../models/M2.md#c-p3)。

**机制候选：** [ME06](../MECHANISMS.md#me06)。

**语言模式 LP02：** “如果用另一种方式实现同一目的，会有什么不同？”

**变体与使用条件：** “把 X 换成 Y 后，哪些关键条件变了？” 使用时绑定对象、主体、语境与当前状态；不要重复已经明确的内容。

**操作与输出：** 固定当前目的，选一个可辨认替代手段；比较输入、成本、后果与失去的功能；若替代改变目的，分别登记新目的而非继续声称同一替换。 输出：替代手段与变化条件。

**完成检查：** 目的保持、手段有实质差异。

**主要失效：** 不知目的却随意换方案。

**取舍与扭曲：** 替换可连带改变约束。

**易混对象：** 新目标生成。

**完成检查：** 候选有任务相关差异。
